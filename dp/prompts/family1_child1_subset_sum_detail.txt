SUBSET SUM: FULL PIPELINE FROM SCRATCH
==============================================================
4 images. Teach Subset Sum the same way as the staircase problem.
Do NOT reference the parent knapsack. Build the reasoning from zero.

Pipeline:
  1. Understand the problem (what are we even trying to do?)
  2. Find the choices (the hard part: HOW do we come up with grab/skip?)
  3. Choices become recursion + the full tree
  4. Base cases + the code

Create a tall portrait infographic (1024x1792). Three sections stacked vertically.

SECTION 1, "THE CHOICES" (gold header, about 40%):

Big header: "WHAT HAPPENS WHEN I CHOOSE?"
Subtitle: "Numbers = [3, 2, 7, 1], target = 6. Looking at the first number: 3."

Kit stands at a FORK IN THE ROAD. Two paths diverge.
The number [3] is in front of Kit, glowing.

LEFT PATH (green, "TAKE 3"):
  Kit grabs the token [3] and puts it in a pouch.
  Speech bubble: "I took 3. Now I only need 6 - 3 = 3 more."
  "Remaining numbers: [2, 7, 1]"
  "NEW PROBLEM: can [2, 7, 1] make 3?"

  Show clearly:   target: 6 -> 3    (shrinks by 3!)
                   numbers left: [2, 7, 1]

RIGHT PATH (red, "LEAVE 3"):
  Kit walks past the token. It stays on the table.
  Speech bubble: "I left 3. I still need all 6."
  "Remaining numbers: [2, 7, 1]"
  "NEW PROBLEM: can [2, 7, 1] make 6?"

  Show clearly:   target: 6 -> 6    (stays the same!)
                   numbers left: [2, 7, 1]

Big gold box between the paths:
"BOTH paths give me a SMALLER problem!
Fewer numbers to decide about. THAT'S recursion."

SECTION 2, "HOW DOES THIS SOLVE IT?" (blue header, about 30%):

Header: "Keep choosing until you're done"

Show a chain of decisions (like a comic strip, 3 panels):

Panel 1: "At [3]: Take or Leave?"
  Take 3. target: 6 -> 3. Left: [2, 7, 1]

Panel 2: "At [2]: Take or Leave?"
  Take 2. target: 3 -> 1. Left: [7, 1]

Panel 3: "At [7]: Take or Leave?"
  7 > 1. Can't take (would overshoot). Must Leave.
  target stays 1. Left: [1]

Panel 4: "At [1]: Take or Leave?"
  Take 1. target: 1 -> 0.

Final: "target = 0. I collected EXACTLY 6. Done! Return True."
Show: 3 + 2 + 1 = 6. Green checkmark.

SECTION 3, "THE COMBINE STEP" (amber header, about 30%):

Header: "What if I chose differently?"

"At each number, I tried TAKE. But what if LEAVE was the right choice?
The recursion tries BOTH. If EITHER path reaches target = 0, the answer is True."

Show the formula (BIG):
  can_reach = take_path  OR  leave_path
  "Did EITHER choice lead to success?"

Kit: "I don't need BOTH paths to work. Just ONE path reaching zero is enough."

Comparison to staircase (small box, not the focus):
  "Staircase: ways = climb1 + climb2  (count ALL paths)
   Subset Sum: result = take OR leave  (does ANY path work?)"

SECTION 1, "WHEN DO I STOP?" (amber header, about 30%):

Big header: "BASE CASES"
Subtitle: "The recursion needs to know when to stop."

Two scenarios shown as big cards:

GREEN CARD: "target == 0"
  Kit celebrating, fist pump.
  "I've collected EXACTLY the right amount! Nothing more to do."
  "Return True"
  Show: started needing 6, took 3, took 2, took 1. Now need 0. DONE!

RED CARD: "No numbers left (index == len(nums)) and target > 0"
  Kit with empty hands, looking at empty table.
  "I still need more, but there's nothing left to pick from."
  "Return False"
  Show: started needing 6, took 3, skipped everything else. Still need 3. No items. FAIL.

Small note: "What about target < 0? That can't happen if we check before taking.
If the number is bigger than what I need, I just leave it."

SECTION 2, "THE CODE" (gray/blue header, about 40%):

Header: "FROM REASONING TO CODE"
Subtitle: "Every line comes directly from our choices."

Show the code with LARGE font. Next to each block, show which part of the
reasoning it encodes:

  def can_reach(nums, target, index):

      if target == 0:              <- "Collected enough! Done. True."
          return True

      if index == len(nums):       <- "Nothing left to pick. Failed. False."
          return False

      if nums[index] > target:     <- "This number is too big.
          return can_reach(            Would overshoot. Must leave it."
              nums, target,
              index + 1)

      take = can_reach(            <- "TAKE this number.
          nums,                        target SHRINKS by this amount.
          target - nums[index],        Move to next number."
          index + 1)

      leave = can_reach(           <- "LEAVE this number.
          nums,                        target STAYS the same.
          target,                      Move to next number."
          index + 1)

      return take or leave         <- "Did EITHER choice work?"

Use arrows connecting each annotation to the corresponding code lines.
Annotations are in cream-colored rounded boxes.

SECTION 3, "THE PATTERN" (gold header, about 30%):

Header: "SEE THE STRUCTURE"

Show the three key pieces side by side in a summary:

  CHOICES:      take or leave (at each number)
  SMALLER:      fewer numbers left to decide about
  COMBINE:      take OR leave (either path working = True)
  STOP:         target = 0 (success!) or no items (failure)

Kit's final speech bubble:
"Every recursion problem follows this pattern.
Find the choices. Show they make the problem smaller.
Pick how to combine. Define when to stop.
The code writes itself."

Gold box at very bottom:
"NEXT: this same structure, with different COMBINE steps,
gives you Count Subsets (+), Equal Partition, Target Sum, and more."
