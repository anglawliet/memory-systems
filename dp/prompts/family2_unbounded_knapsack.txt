UNBOUNDED KNAPSACK: INTUITIVE PIPELINE FROM SCRATCH
==============================================================
4 images. Teach unbounded knapsack from zero. No references to 0/1 knapsack.
Build intuition so the learner can DERIVE the solution independently.

Pipeline:
  1. Understand the problem + why brute force fails
  2. Find the choices (THE most important, spend most time here)
  3. Base cases + recursion tree
  4. Code (derived from reasoning) + pattern recognition

No tabulation. No memoization. Pure recursive thinking.

  Kit walks past Gold. It fades behind him.
  Three things shown clearly:
    "Value: no change"
    "Bag: stays 5kg"
    "Advance to Diamond (done with Gold FOREVER)"

BIG CHOICE DIAGRAM (centered, gold background card, the visual centerpiece):

  +---------------------------------------+
  | At item[index], bag_limit remaining   |
  | "What can I do with this ONE item?"   |
  +------------------+--------------------+
  | USE IT           | MOVE ON            |
  | (stay)           | (advance)          |
  |                  |                    |
  | Add its value    | Skip this item     |
  | Bag shrinks      | Bag stays same     |
  | index STAYS      | index advances     |
  | "might want more"| "done forever"     |
  +------------------+--------------------+

Below the diagram, in amber:
  "Why are these the ONLY choices?"
  "I either want this item or I don't."
  "Want more? USE and STAY. Done? MOVE ON."

SECTION 2, "HOW DOES THIS ACTUALLY SOLVE IT?" (blue header, about 30%):

Header: "Watch the choices play out"

Show a chain of decisions (like a comic strip, 4 panels):

Panel 1: "At Gold (3kg, $4), bag=5."
  USE Gold. Value: +$4. Bag: 5->2. STAY at Gold.

Panel 2: "At Gold (3kg, $4), bag=2."
  3kg > 2kg. Doesn't fit! Forced to MOVE ON.

Panel 3: "At Ruby (1kg, $2), bag=2."
  USE Ruby. Value: +$2. Bag: 2->1. STAY at Ruby.

Panel 4: "At Ruby (1kg, $2), bag=1."
  USE Ruby. Value: +$2. Bag: 1->0. Done!
  "Gold + Ruby + Ruby = $4+$2+$2 = $8"

SECTION 3, "THE COMBINE STEP" (amber header, about 25%):

"Both choices give me a VALUE.
I pick whichever gives MORE."

Show the formula (BIG):
  use_again = value + solve(remaining with SAME item)
  move_on = solve(remaining with NEXT item)
  answer = max(use_again, move_on)

Kit: "At every item, I try both. Keep the better one.
The recursion tries ALL paths and picks the best."

            bag 4->1           (go to Ruby)
                |                    |
          (Gold, bag=1)        (Ruby, bag=4)
          3>1, won't fit       /            \

       Return $0         ...continues...

---BEGIN STYLE BIBLE---
[Paste the full style bible from above here]

Create a tall portrait infographic (1024x1792). Two sections.

SECTION 1, "FROM REASONING TO CODE" (gray header, about 60%):

Big header: "EVERY LINE COMES FROM A DECISION"

Show the code with LARGE font. Next to EACH block, an annotation in a cream-colored
rounded box connected by an arrow, explaining WHY that line exists:

  def max_value(treasures, bag_limit, index):

      if index == len(treasures) or bag_limit == 0:
          return 0
  Arrow: "Base cases: no items left OR bag full. Can't add value."

      name, weight, value = treasures[index]
  Arrow: "Look at the current item."

      if weight > bag_limit:
          return max_value(treasures, bag_limit, index + 1)
  Arrow: "Doesn't fit? Forced to move on."

      use_again = value + max_value(
          treasures,
          bag_limit - weight,
          index)
  Arrow: "USE IT. Add value. Bag shrinks. STAY (same index)."

      move_on = max_value(
          treasures,
          bag_limit,
          index + 1)
  Arrow: "MOVE ON. No value. Bag same. Next item."

      return max(use_again, move_on)
  Arrow: "Which choice gave more value? Keep that one."

SECTION 2, "PATTERN RECOGNITION" (gold header, about 40%):

Header: "WHEN YOU SEE THIS PATTERN AGAIN"

A prominent PATTERN RECOGNITION CARD (teal border, gold background):

  CLUE WORDS: "unlimited supply", "reusable items",
              "as many times as you want"

  CHOICES: USE this item (STAY) or MOVE ON (advance).

  STATE: (index, remaining_capacity)

  COMBINE: depends on what you're asked:
    "Maximize value?" -> max(use, move_on)
    "Minimize count?" -> min(use, move_on)
    "Count ways?"     -> use + move_on

  "The CHOICES never change. Only the COMBINE step changes."

Kit's speech bubble:
  "See 'unlimited supply' + 'optimize something'?
   Think: use again or move on. That's your starting point."

Gold box at bottom:
  "NEXT: Coin Change, Coin Change 2, Word Break.
   Same choices. Different combine."
