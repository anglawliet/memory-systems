UNBOUNDED KNAPSACK: FULL PIPELINE FROM SCRATCH
==============================================================
4 images. Teach unbounded knapsack the same way as staircase/subset sum.
Key difference from 0/1: you can REUSE items. The choice becomes
"take AGAIN (stay)" vs "move on (next item)."

Big gold comparison box (THE KEY):
  0/1 KNAPSACK:                     UNBOUNDED KNAPSACK:
  TAKE: index + 1 (move on)         TAKE AGAIN: index (STAY!)
  SKIP: index + 1 (move on)         MOVE ON: index + 1 (advance)
  "Both choices advance"            "Only MOVE ON advances"

  "In 0/1, after taking, you're DONE with that item."
  "In unbounded, after taking, the item is STILL THERE."

SECTION 2, "WHY THIS WORKS" (blue header, about 30%):

Header: "STAY means I can take it multiple times"

Show a chain of decisions for Gold Bar at capacity 5:
  Step 1: At Gold (3kg, $4), cap=5. TAKE AGAIN. Cap: 5->2. Stay at Gold.
  Step 2: At Gold (3kg, $4), cap=2. 3>2, can't take. Forced to MOVE ON.
  "Took Gold once. Would've taken it again but it doesn't fit anymore."

Another example:
  Ruby (1kg, $2), cap=5.
  TAKE AGAIN. cap=4. Stay.
  TAKE AGAIN. cap=3. Stay.
  TAKE AGAIN. cap=2. Stay.
  TAKE AGAIN. cap=1. Stay.
  TAKE AGAIN. cap=0. Base case! 5 Rubies, $10.

SECTION 3, "THE COMBINE STEP" (amber header, about 25%):

  take_again = value + max_value(treasures, bag_limit - weight, index)
  move_on = max_value(treasures, bag_limit, index + 1)
  return max(take_again, move_on)

  "Same as 0/1: pick the better option. max(take_again, move_on)."
  "The ONLY change is where 'index' goes after taking."

Kit: "One tiny change in the recursion: index stays instead of advancing.
That one change turns 0/1 into unbounded."

Create a tall portrait infographic (1024x1792). Three sections.

SECTION 1, "BASE CASES" (amber header, about 20%):

Two cards:

  RED: "index == len(treasures): return 0. No items left to consider."

SECTION 2, "THE CODE" (gray header, about 40%):

Header: "ONE LINE DIFFERENT FROM 0/1"

Show the code. HIGHLIGHT the ONE line that changed:

  def max_value(treasures, bag_limit, index):
      if index == len(treasures) or bag_limit == 0:
          return 0

      name, weight, value = treasures[index]

      if weight > bag_limit:
          return max_value(treasures, bag_limit, index + 1)

      take_again = value + max_value(
          treasures,
          bag_limit - weight,
          index)                    # <-- THIS LINE! index, not index + 1

      move_on = max_value(
          treasures,
          bag_limit,
          index + 1)

      return max(take_again, move_on)

Draw a BIG arrow pointing to "index" in the take_again call.
Gold highlight box: "THIS is the ONLY difference from 0/1.
'index' instead of 'index + 1'. Stay instead of advance."

SECTION 3, "0/1 vs UNBOUNDED: THE FULL COMPARISON" (teal header, about 40%):

Header: "SIDE BY SIDE"

Show the two codes next to each other, differences highlighted:

  0/1 KNAPSACK:                    UNBOUNDED KNAPSACK:
  grab = value + max_value(        take_again = value + max_value(
      treasures,                       treasures,
      bag_limit - weight,              bag_limit - weight,
      index + 1)   <-- ADVANCE        index)        <-- STAY
  skip = max_value(                move_on = max_value(
      ...)                             ...)
  return max(grab, skip)           return max(take_again, move_on)

  TABULATION:                      TABULATION:
  Inner loop RIGHT to LEFT         Inner loop LEFT to RIGHT
  "Prevents reuse"                 "ALLOWS reuse"

Show the loop direction visually:
  0/1:        [0] [1] [2] [3] [4] [5]
              <-------- RIGHT TO LEFT
              "Each cell sees LAST row's values. Item used once."

  Unbounded:  [0] [1] [2] [3] [4] [5]
              LEFT TO RIGHT -------->
              "Each cell sees THIS row's updates. Item reused!"

Kit: "One line in recursion. One loop direction in tabulation.
That's the entire difference between the two families."

Gold box: "NEXT: The children. Coin Change, Coin Change 2, Word Break.
Same 'take again or move on' choice, different combine step."
