STYLE BIBLE
================================================================================

---BEGIN STYLE BIBLE---

IMAGE FORMAT: Tall portrait infographic (1024x1792).

TEXT RULES:
- ALL text must be HUGE. Section titles 60pt+, body text 32pt+, code 26pt+.
- Every element must be readable on a phone held vertically WITHOUT zooming.
- Maximum 15 words per explanation. Let the visuals carry the meaning.
- White space is OK. Don't cram. Better to be clear than dense.
- All text rendered in a clean sans-serif font (like Nunito or Poppins).
  NO chalk-style text, NO handwritten fonts, NO serif fonts.

CHARACTER (Kit, appears in EVERY image with this EXACT look):
- Young person, mid-20s, master vault raider.
- Hair: SHORT MESSY DARK BROWN hair. Never long, never neat, never styled.
- Face: sharp dark eyes, confident smirk, light stubble. Round head.
- Outfit (EVERY image, NO exceptions):
  * SLEEK BLACK TACTICAL SUIT (one-piece, fitted, matte black).
  * DARK BLUE UTILITY BELT around the waist.
  * FINGERLESS BLACK GLOVES on both hands.
  * Compact NIGHT-VISION GOGGLES pushed up on forehead (always visible).
- Build: lean and athletic. Calm, calculated confidence.
- Proportions: Pixar/Disney-style 3D render. Head slightly oversized
  (about 1/4 of body height). Big eyes. Smooth plastic-like skin.

ART STYLE:
- Soft 3D cartoon render (Pixar energy). NOT flat, NOT photorealistic, NOT anime.
- Smooth rounded shapes, soft shadows, slight subsurface scattering on skin.
- Clean vector-like line quality on diagrams and text boxes.

COLOR PALETTE:
- Background: dark purple-blue (#1E1035). Grid/matrix atmosphere.
- Section cards: cream/warm-white (#FFF8F0) with rounded corners, subtle shadow.
- Headers: bright purple (#8B5CF6).
- Code blocks: light gray (#F3F4F6) rounded boxes, large monospace font.
- Gold accents: (#F59E0B) for callouts and highlights.
- Green: (#22C55E) for match/free paths. Red: (#EF4444) for mismatch/cost.
- Amber: (#F59E0B) for replace. Blue: (#3B82F6) for insert.
- Purple accent lighting throughout.

---END STYLE BIBLE---

Label: "TAKE THE MATCH"
"Both characters consumed. +1 to the length."
Arrow: "i+1, j+1"

Kit gives a thumbs up.

Small gold text: "For LCS, a free match is always worth taking. Skipping a match can never help when maximizing length."

SECTION 2: "NO MATCH: text1[i] != text2[j]" (RED card, about 40%):

Show two letter boxes:
text1[i] = 'b' and text2[j] = 'c'. Red highlight. Not-equals sign between them.

TWO branching arrows from this state:

LEFT BRANCH (amber border):
Label: "SKIP text1[i]"
"Maybe 'b' is useless here."
Arrow: "i+1, j stays"
Show only i pointer moving right, j stays.

RIGHT BRANCH (amber border):
Label: "SKIP text2[j]"
"Maybe 'c' is useless here."
Arrow: "i stays, j+1"
Show only j pointer moving right, i stays.

Below both branches:
"result = max(skip_text1, skip_text2)"
"LONGEST. So take the BETTER path."

SECTION 3: "WHY NOT SKIP BOTH?" (small RED rejection card, about 15%):

Red X mark.
"Skipping both at once would miss cases where one of them matches something later."
"Already covered: each skip branch tries the other character against future ones."

---BEGIN STYLE BIBLE---
[Paste the full style bible from above here]
---END STYLE BIBLE---

Create a tall portrait infographic (1024x1792). Three sections.

Big header at top: "WHY DOES EACH VARIABLE CHANGE?"

Show two rows of letter boxes at the top:
Row 1 (labeled "text1"): a b c d e
Row 2 (labeled "text2"): a c e
Pointer "i" on text1, pointer "j" on text2.

SECTION 1: "MATCH: text1[i] == text2[j], take it" (GREEN card, about 30%):

  Action: "Pair them. This match adds 1 to the LCS length."

  Show i pointer moving right by 1: "i -> i+1"
  Text: "text1[i] consumed. Used for the match."

  Show j pointer moving right by 1: "j -> j+1"
  Text: "text2[j] consumed. Same character matched."

  Call: "1 + lcs(i+1, j+1)"

  Why both? "A match uses one character from EACH string. Both must advance."

SECTION 2: "NO MATCH, SKIP text1[i]" (AMBER card, about 25%):

  Action: "text1[i] can't pair with text2[j]. Skip past it."

  Show i pointer moving right by 1: "i -> i+1"
  Text: "text1[i] skipped. Move past it."

  Show j pointer staying in place: "j stays"
  Text: "text2[j] NOT consumed. Still looking for a match."

  Call: "lcs(i+1, j)"

  Why j stays? "text2[j] might match a later text1 character."

SECTION 3: "NO MATCH, SKIP text2[j]" (AMBER card, about 25%):

  Action: "text2[j] can't pair with text1[i]. Skip past it."

  Show i pointer staying: "i stays"
  Text: "text1[i] NOT consumed. Still looking for a match."

  Show j pointer moving right by 1: "j -> j+1"
  Text: "text2[j] skipped. Move past it."

  Call: "lcs(i, j+1)"

  Why i stays? "text1[i] might match a later text2 character."

Kit at the bottom with text: "Match: both advance. Skip: only the skipped one advances."
