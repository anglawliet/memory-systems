LIS ONE RECURSIVE CALL (landscape, two real choices that MERGE)
==============================================================
Landscape 1536x1024. Explains exactly ONE invocation of
lis(numbers_index, must_be_bigger_than).

SHAPE, THE KEY DIFFERENCE FROM LCS: take and skip are two REAL
CHOICES, not an if / else. BOTH are explored, so the two columns DO
merge at the bottom into one shared max box. There is NO dashed
"only one branch runs" divider here.
The validity check gates ONLY the take branch. Skip is always legal.

CODE FLOW: read top to bottom in the order the function runs.
   STEP 1  base case guard
   STEP 2  two choices from here
   STEP 3  left column,  TAKE (gated by the check)
   STEP 4  right column, SKIP (always allowed)
   STEP 5  return max( take , skip )

STATE: numbers_index points INTO the array, so it is drawn as a
square on the bar. must_be_bigger_than is a VALUE we carry, not a
position, so it is drawn as a separate chip beside the bar. That
distinction is the whole point of the naming.

DE-CLUTTER: the array is a plain flat GREY BAR. Only the ONE current
element is highlighted. Used parts are faded and crossed out.
Calls are EXPRESSIONS with the numeric form under them.
State chosen so the take is VALID, so the "1 +" is a live path.
==============================================================

a pointer into the array. This chip is the memory of the last number that was
taken, and it is the only thing standing between us and a non-increasing pick.
