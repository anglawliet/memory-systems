  In REST: buy or wait? -> max(buy, wait)
  In HOLD: sell or keep? -> max(sell, keep)
  In SOLD: must cool down -> only one path

SECTION 2, "THE STATE" (emerald header, about 30%):

Header: "WHAT DO I NEED TO KNOW?"

  [CHECK] day - which day am I on?
  [CHECK] current state - am I in HOLD, SOLD, or REST?
  [X] prices - never change
  [X] total profit so far - recursion accumulates this

"State = (day, state). TWO variables: WHEN and WHAT STATE."

Gold box: "Different from 2D table DP!
There, both variables are indices in strings.
Here, one variable is time, the other is a categorical state."

SECTION 3, "BASE CASES" (emerald header, about 30%):

Header: "WHEN DO I STOP?"

  BASE CASE: day == len(prices)
  "No more trading days. Game over."
  return 0 (regardless of state)

Kit: "Only one base case. When time runs out, profit is 0."

Gold box: "Start state: day=0, state=REST (free to buy on day 1).

Subtitle: "prices = [1, 2, 3, 0, 2]"

Draw the recursion tree. Each node shows (day, state).
Color-code by state: RED=HOLD, GREEN=SOLD, BLUE=REST.

  (0, REST)
    |
  buy: (1, HOLD)           wait: (1, REST)
    |       |                 |       |
  sell:   keep:            buy:    wait:
  (2,SOLD) (2,HOLD)       (2,HOLD) (2,REST)
    |        |   |           |  |      |   |
  cool:   sell: keep:     sell: keep: buy: wait:
  (3,REST) (3,S) (3,H)   (3,S) (3,H) (3,H) (3,R)

CIRCLE overlapping subproblems with GOLD borders:
  (2, HOLD) appears from two different paths!
  (3, REST) appears from multiple paths!

"Same day, same state, from different trading histories."
"The history doesn't matter. Only WHERE you are NOW matters."

Kit: "The overlap happens because different sequences of buys and sells
can land you in the same (day, state). That's why it's DP."

SECTION 2, "THE STATE SPACE" (gold header, about 45%):

Header: "ONLY 3n UNIQUE STATES"

Show a grid: 5 rows (days 0-4) x 3 columns (HOLD, SOLD, REST).
= 15 cells total.

"Without cache: tree branches exponentially."
"With cache: at most 3 x 5 = 15 unique states."

Color each cell by state:
  RED cells for HOLD column
  GREEN cells for SOLD column
  BLUE cells for REST column

Mark cells that were computed more than once with GOLD borders.

Kit: "15 cells. That's it. The entire problem fits in a 5x3 grid.
Each cell computed exactly once."

Gold box: "Key insight: in tabulation, you don't even need the grid.
Each day only needs yesterday's values. 3 variables!"

PROMPT 3: LIS Choice Diagram -> lis_choices.png
================================================================================

---BEGIN STYLE BIBLE---
[Paste the full style bible from above here]
---END STYLE BIBLE---

Create a tall portrait infographic (1024x1792). Three sections.

SECTION 1, "THE CHOICES" (emerald header, about 40%):

Big header: "LIS: FIND THE CHOICES"
Subtitle: "nums = [10, 9, 2, 5, 3, 7, 101, 18]. Longest increasing subsequence?"

Show the array with values and indices.
Highlight index 5 (value 7).

"THE KEY QUESTION: What could come BEFORE 7 in an increasing subsequence?"

Draw arrows from index 5 BACKWARD to every element that is smaller:
  index 2 (value 2): 2 < 7 CHECK. lis[2] + 1 = 2
  index 3 (value 5): 5 < 7 CHECK. lis[3] + 1 = 3
  index 4 (value 3): 3 < 7 CHECK. lis[4] + 1 = 3

Cross out elements that are NOT smaller:
  index 0 (value 10): 10 > 7 X
  index 1 (value 9): 9 > 7 X

CHOICE: "For each j before i where nums[j] < nums[i]:
Can I extend that subsequence? Take the LONGEST one."

lis[5] = 1 + max(lis[2], lis[3], lis[4]) = 1 + 2 = 3

Kit: "Not fixed branches like LCS. VARIABLE lookback.
Check EVERY previous element. Keep the best."

SECTION 2, "VS OTHER PATTERNS" (emerald header, about 30%):

COMPARISON:
  LCS: "Compare chars at (i,j). Fixed 2 or 3 choices."
  Knapsack: "Grab or skip item i. Fixed 2 choices."
  LIS: "Extend from ANY valid j. Variable number of choices!"

"LIS is different: the number of choices depends on the data."

Kit: "In knapsack, you always have 2 choices.
In LIS, you might have 0, 1, or 5 valid predecessors."

SECTION 3, "STATE + BASE CASES" (emerald header, about 30%):

State = just index i (1D, not 2D!).
lis_ending_at(i) = length of longest increasing subsequence ENDING at i.

"Ending at" is the key. Not "starting from", not "using first i elements".
The answer is max over ALL positions: max(lis[0], lis[1], ..., lis[n-1]).

BASE CASE:
  Every element by itself is a subsequence of length 1.
  lis[i] starts at 1 for all i.

Kit: "State is 'best ending HERE'. You check every earlier position.
The answer isn't at the last cell. It's the MAX across all cells."

================================================================================

---BEGIN STYLE BIBLE---

Create a tall portrait infographic (1024x1792). Three sections.

SECTION 1, "THE WRONG WAY" (red header, about 30%):

Big header: "BURST BALLOONS: THE TRAP"
Subtitle: "nums = [3, 1, 5, 8]. Burst for max coins."

"WRONG: Think about which to burst FIRST."
Show bursting balloon 1 (value 1) first:
  coins = 3 * 1 * 5 = 15. But now 3 and 5 are NEIGHBORS!
  "The neighbors CHANGE after each burst. Subproblems aren't independent!"

Draw an X over this approach.
Kit shaking head: "Burst first? Neighbors shift. Subproblems overlap messily."

SECTION 2, "THE RIGHT WAY" (emerald header, about 40%):

Header: "THE REVERSAL: THINK LAST, NOT FIRST"

"RIGHT: Think about which to burst LAST in range [left, right]."

Show balloons with boundary 1s: [1] 3  1  5  8 [1]

"If balloon k is the LAST to burst in [left, right]..."
"Everything else is ALREADY GONE."
"Neighbors of k are the BOUNDARIES: nums[left-1] and nums[right+1]."
"coins = nums[left-1] * nums[k] * nums[right+1]"

CHOICE DIAGRAM:

  Current: max_coins(left, right)
  "Which balloon to burst LAST?"
          |
     _____|_____|_____
    |     |     |     |
  last=L  ...  ...  last=R
    |
  coins = boundary_left * nums[last] * boundary_right
        + max_coins(left, last-1)
        + max_coins(last+1, right)

"Try every balloon as the LAST. Two independent subproblems!"

Kit: "Burst LAST = boundaries are fixed = subproblems are independent.
That's the key reversal."

SECTION 3, "STATE + BASE CASES" (emerald header, about 30%):

State = (left, right). An INTERVAL, not two string positions.

"Same 2D state as palindrome DP! Both are interval problems."

BASE CASE:
  left > right? Empty range. No balloons. return 0.

Kit: "Interval DP: state is a range [left, right].
Fill by interval LENGTH (short to long), just like palindrome."

Gold box: "Family connection: palindrome and burst balloons
are BOTH interval DP. Same fill order (by length).
Different cell formula, same table shape."
