The key insight: You don't memorize a template and apply it. You discover the recursion from choices, notice overlapping subproblems, and derive the table from the recursion. The table isn't magic. It comes from the code you already wrote.

Three Golden Rules

1. Find the CHOICES First
At each step, what can you do? Take or skip? Include or exclude? Match, insert, or delete? The choice diagram IS the recursion. Once you see the choices, the code follows.
2. Changing Variables = Table Dimensions
Look at your recursive function's parameters. Which ones change across calls? 1 variable changes → 1D array. 2 variables change → 2D table. The table shape is never a guess.
3. One Parent, Many Children
Each DP family has a parent problem. Every variation is ONE tweak from the parent. Learn the parent deeply. Solve the children by identifying what changed.

Step 1: What Are My Choices?

This is how EVERY knapsack problem starts. At each treasure, Kit has two choices:

THE CHOICE DIAGRAM
At each item: Does it FIT in the bag? (weight <= remaining capacity?)

IF IT FITS (two branches):
    ✅ GRAB: add value, reduce capacity, move to next item
    ❌ SKIP: keep capacity, move to next item
    → Take the MAX of both paths

IF IT DOESN'T FIT (one branch only):
    ❌ SKIP: move to next item (no choice!)
Aditya Verma's Rule: Every DP problem has CHOICES. Find the choices FIRST. The recursion follows.

Step 2: Choices → Recursion (the code writes itself)

The choice diagram IS the recursive function. Each branch = a recursive call.

treasures = [('Gold',4,10), ('Ruby',3,7), ('Diamond',5,12), ('Emerald',1,3), ('Platinum',2,5)]

def max_value(treasures, bag_limit, count):
    if count == 0 or bag_limit == 0:
        return 0

    name, weight, value = treasures[count - 1]

    if weight <= bag_limit:
        grab = value + max_value(treasures, bag_limit - weight, count - 1)
        skip = max_value(treasures, bag_limit, count - 1)
        return max(grab, skip)
    else:
        return max_value(treasures, bag_limit, count - 1)
Choice Diagram
if weight <= bag_limit → "Does it fit?"
grab = value + ... → GREEN path
skip = ... → RED path
max(grab, skip) → "Take the better one"
Base Case
count == 0 → No items left
bag_limit == 0 → No capacity left
Either way → value is $0
Base case = smallest valid input
Why count - 1?
count is how many items we're considering (1 to 5). But Python lists start at index 0.
So treasures[count - 1] just says: "the count-th item is at index count - 1."
When count = 3, we want the 3rd item (Diamond), which is at index 2.

Step 3: Draw the Tree, Spot the Overlap

Using 4 treasures: Gold (4kg), Ruby (3kg), Emerald (1kg), Platinum (2kg), W=7.

The recursion processes items in reverse: Platinum (n=4), Emerald (n=3), Ruby (n=2), Gold (n=1).

Two different paths through the tree arrive at the SAME subproblem:

Path A
(4, 7) start
→ GRAB Platinum (2kg)
→ (3, 5)

→ (1, 4)

Path B
(4, 7) start

→ (3, 7)

Used 3kg (Ruby). Plat and Emer skipped. 4kg left for Gold.
SAME SUBPROBLEM: (n=1, W=4)
Both paths ask: "Only Gold left (4kg/$10K), bag has 4kg. What's the max?"

A problem is DP when:
1.
You make CHOICES (grab or skip)
2.
The SAME subproblem appears MULTIPLE times in the recursive tree
3.
Each subproblem has the SAME answer every time

Step 4: Memoize (3 extra lines)

Same recursive code. Just add a cache. That's it.

def max_value(treasures, bag_limit, count, memo={}):
    if (count, bag_limit) in memo:
        return memo[(count, bag_limit)]          # ALREADY SOLVED? Return it!
    if count == 0 or bag_limit == 0:
        return 0
    name, weight, value = treasures[count - 1]
    if weight <= bag_limit:
        grab = value + max_value(treasures, bag_limit - weight, count - 1, memo)
        skip = max_value(treasures, bag_limit, count - 1, memo)
        result = max(grab, skip)
    else:
        result = max_value(treasures, bag_limit, count - 1, memo)
    memo[(count, bag_limit)] = result            # STORE result
    return result
Without cache: O(2n)
Every branch explored, including duplicates.
With cache: O(n × W)
Every unique (n, W) pair solved at most once.

Step 5: From Recursion to Table (one question at a time)

Every part of the table comes from a specific line in the recursion. Nothing is invented. Let's derive it question by question.

Q: Why a table? Why 2D?

Look at your recursive function signature:

def max_value(treasures, bag_limit, count):

Cross out what stays the same across every recursive call:

treasures
Same list every call
crossed out ✗
bag_limit
Goes down when you GRAB an item
CHANGES ✓
count
Goes down as you move to the next item
CHANGES ✓

2 variables change → 2D table. One dimension for each changing variable. That's it.

If only 1 variable changed, it would be a 1D array. If 3 changed, it would be 3D. The number of changing variables = number of dimensions. Always.

Q: What are the rows? What are the columns?

The two changing variables are count (items) and bag_limit (capacity). Each becomes one axis:

Rows = items considered
Row 0 = no items available
Row 1 = only Gold available
Row 2 = Gold + Ruby available
...
Row 5 = all 5 treasures available
Columns = bag capacity
Col 0 = bag holds 0 kg
Col 1 = bag holds 1 kg
Col 2 = bag holds 2 kg
...
Col 7 = bag holds 7 kg

So table[row][cap] answers: "What's the best value using the first row treasures with a bag that holds cap kg?"

This is exactly what the recursion computes. The table just stores every answer so you don't recompute.

Q: Why is the first row all zeros?

Look at your recursive base case:

count == 0 means "no items to consider." Row 0 in the table is exactly that: zero items available.

With zero items, no matter how much capacity you have (0 kg, 1 kg, ... 7 kg), the best value is always $0. You have nothing to grab.

Q: How do I fill each cell? Where does the formula come from?

Straight from the recursion. There are two cases:

Case 1: Item DOESN'T FIT (weight > capacity)
RECURSION SAYS:
return max_value(treasures, bag_limit, count - 1)
"This item doesn't fit. Pretend it doesn't exist. Solve with one fewer item, same capacity."
→
TABLE SAYS:
table[row][cap] = without_this[cap]
Copy from directly above.
without_this = the row above (the world before this item existed).
Same column (same capacity).
Case 2: Item FITS (weight <= capacity)
RECURSION SAYS:
grab = value + max_value(bag_limit - weight, count - 1)
skip = max_value(bag_limit, count - 1)
return max(grab, skip)
→
TABLE SAYS:
grab = value + without_this[cap - weight]
skip = without_this[cap]
table[row][cap] = max(grab, skip)
GRAB = this item's value + best value with remaining capacity from earlier items
    without_this = the row above (the world before this item existed)
    [cap - weight] = column shifted left by this item's weight (capacity used up)

SKIP = best value without this item, same capacity
    without_this[cap] = row above, same column (just ignore this item entirely)

Pick whichever is better.

Q: Why do some cells just copy the value from the row above?

Let's fill Gold's row, capacity 2: only Gold available, bag holds 2 kg.

Item: Gold, weight = 4 kg, value = $10K
Bag capacity: 2 kg
Does it fit? weight 4 <= capacity 2? NO. Gold is too heavy.

Kit has no choice. Gold doesn't fit. Skip it.
Copy from the row above ("no items" row at 2 kg) = 0

This is why you see many cells with the same value as the cell above. It means: "this item was too heavy for this capacity, so adding it to the available items changed nothing."

Look at Gold's row: at 0 kg through 3 kg, all zeros, copied from the "no items" row above. Gold weighs 4 kg, so it doesn't fit until capacity 4. At 4 kg, Gold finally fits, and the value jumps to $10K.

The Tabulation Code

Every line maps to something we just derived:

def max_value(treasures, bag_limit):
    table = [[0] * (bag_limit + 1)                  # first row + col = all zeros (base case)
             for _ in range(len(treasures) + 1)]
    for row in range(1, len(treasures) + 1):         # row by row (each item)
        name, weight, value = treasures[row - 1]     # row 1 = Gold (index 0), row 2 = Ruby (index 1)...
        without_this = table[row - 1]                 # the row above = world before this item existed
        for cap in range(1, bag_limit + 1):           # column by column (each capacity)
            if weight <= cap:                          # does this item fit?
                grab = value + without_this[cap - weight]   # GRAB: value + row above, left by weight
                skip = without_this[cap]                     # SKIP: row above, same column
                table[row][cap] = max(grab, skip)            # pick the better one
            else:
                table[row][cap] = without_this[cap]  # NO: copy from above (can't use this item)
    return table[len(treasures)][bag_limit]           # bottom-right = all items, full capacity
The 0/1 Knapsack Family
One parent, six children. Learn the parent. Every variation is ONE tweak.
0/1 KNAPSACK (parent)
At each item: grab or skip. Maximize total value within capacity.

1 Subset Sum

▶
THE TWEAK
Values = weights. Answer is True/False, not max. "Can I pick items that sum to exactly S?"
def subsetSum(nums, target):
    dp = [False] * (target + 1)
    dp[0] = True
    for num in nums:
        for j in range(target, num - 1, -1):
            dp[j] = dp[j] or dp[j - num]
    return dp[target]

2 Equal Sum Partition

▶
THE TWEAK
Target = totalSum / 2, then run Subset Sum. "Can I split into two groups with equal sum?" If total is odd, immediately False.
def canPartition(nums):
    total = sum(nums)
    if total % 2: return False
    return subsetSum(nums, total // 2)

3 Count of Subsets with Sum

▶
THE TWEAK
Replace max() with +=. Count instead of optimize. "HOW MANY subsets sum to S?"
def countSubsets(nums, target):
    dp = [0] * (target + 1)
    dp[0] = 1
    for num in nums:
        for j in range(target, num - 1, -1):
            dp[j] += dp[j - num]
    return dp[target]

4 Minimum Subset Sum Difference

▶
THE TWEAK
Use Subset Sum table's last row to find which sums are achievable. Pick the achievable sum closest to totalSum/2. Difference = totalSum - 2 * closestSum.
def minimumDifference(nums):
    total = sum(nums)
    half = total // 2
    dp = [False] * (half + 1)
    dp[0] = True
    for num in nums:
        for j in range(half, num - 1, -1):
            dp[j] = dp[j] or dp[j - num]
    for j in range(half, -1, -1):
        if dp[j]:
            return total - 2 * j

5 Target Sum (LeetCode #494)

▶
THE TWEAK
Assign +/- to each number to reach target. Math reduction: P - (total - P) = target, so P = (total + target) / 2. Then Count of Subsets with Sum = P.
def findTargetSumWays(nums, target):
    total = sum(nums)
    if (total + target) % 2 or abs(target) > total: return 0
    goal = (total + target) // 2
    dp = [0] * (goal + 1)
    dp[0] = 1
    for num in nums:
        for a in range(goal, num - 1, -1):
            dp[a] += dp[a - num]
    return dp[goal]

6 Count Subsets with Given Difference

▶
THE TWEAK
S1 - S2 = diff. Same math as Target Sum: target = (total + diff) / 2, then Count of Subsets.
def countWithDiff(nums, diff):
    total = sum(nums)
    if (total + diff) % 2 or abs(diff) > total: return 0
    target = (total + diff) // 2
    dp = [0] * (target + 1)
    dp[0] = 1
    for num in nums:
        for j in range(target, num - 1, -1):
            dp[j] += dp[j - num]
    return dp[target]
Key pattern for the whole family: 0/1 = each item used at most once, so the 1D inner loop goes RIGHT to LEFT. This prevents using the same item twice. If the inner loop went left to right, earlier updates would be read by later cells, effectively reusing the item (that's Unbounded Knapsack, a different family).
Common Mistakes
WRONG: inner loop left to right

    dp[j] += dp[j - num]
# Same item counted MULTIPLE times!
# This is unbounded knapsack, not 0/1.
RIGHT: right to left for 0/1
for j in range(target, num - 1, -1):
    dp[j] += dp[j - num]
# Each item used at most once.
# RIGHT to LEFT = 0/1 knapsack.
WRONG: skipping the math reduction

# of +/- signs with recursion.
# Exponential time, no DP insight.
RIGHT: reduce to Count of Subsets

21 Problems by Family

Linear Fibonacci / Linear Recurrence

1 Climbing Stairs (#70) Easy

▶
PROBLEM
You are climbing a staircase. It takes n steps to reach the top. Each time you can climb 1 or 2 steps. In how many distinct ways can you climb to the top?
THE CHOICES
At each step: climb 1 or climb 2. Two choices, each leads to a smaller subproblem. Ways to reach step i = ways from (i-1) + ways from (i-2). Pure Fibonacci.
WHY IT'S DP
"How many ways to reach step 5?" calls step 4 and step 3. "Step 4?" calls step 3 and step 2. Step 3 appears twice. Same subproblem, same answer.
def climbStairs(n):
    if n <= 2: return n
    prev2, prev1 = 1, 2
    for i in range(3, n + 1):
        prev2, prev1 = prev1, prev1 + prev2
    return prev1

2 Min Cost Climbing Stairs (#746) Easy

▶
PROBLEM
Given an array cost where cost[i] is the cost of step i, find the minimum cost to reach the top. You can start from step 0 or step 1, and climb 1 or 2 steps at a time.
THE CHOICES
At each step: arrive from (i-1) paying cost[i-1], or from (i-2) paying cost[i-2]. Pick the cheaper path.
def minCostClimbingStairs(cost):
    prev2, prev1 = 0, 0
    for i in range(2, len(cost) + 1):
        prev2, prev1 = prev1, min(prev1 + cost[i-1], prev2 + cost[i-2])
    return prev1

3 Decode Ways (#91) Medium

▶
PROBLEM
Given a string of digits, determine the total number of ways to decode it. 'A'=1, 'B'=2, ..., 'Z'=26.
THE CHOICES
At position i: decode 1 digit (if valid, i.e. not '0') or decode 2 digits (if the pair is 10-26). Conditional Fibonacci: not always looking back 2.
def numDecodings(s):
    if s[0] == '0': return 0
    prev2, prev1 = 1, 1
    for i in range(1, len(s)):
        curr = 0
        if s[i] != '0':
            curr += prev1
        if 10 <= int(s[i-1:i+1]) <= 26:
            curr += prev2
        prev2, prev1 = prev1, curr
    return prev1

4 Maximum Product Subarray (#152) Medium

▶
PROBLEM
Given an integer array, find a contiguous subarray that has the largest product, and return its product.
THE CHOICES
At each element: extend the current subarray or start fresh. Track BOTH max and min at each step because a negative times a negative becomes positive.
def maxProduct(nums):
    res = max(nums)
    cur_max, cur_min = 1, 1
    for n in nums:
        vals = (n, n * cur_max, n * cur_min)
        cur_max, cur_min = max(vals), min(vals)
        res = max(res, cur_max)
    return res

0/1 Knapsack Take or Skip, Each Item Once

5 House Robber (#198) Medium

▶
PROBLEM
Given an array of non-negative integers representing money in each house, determine the maximum amount you can rob without robbing two adjacent houses.
THE CHOICES
At each house: ROB it (skip previous, take this one's money + best from 2 houses back) or SKIP it (keep the best from previous). Same take-or-skip pattern as knapsack, but the constraint is adjacency instead of capacity.
def rob(nums):
    if len(nums) <= 2: return max(nums)
    prev2, prev1 = nums[0], max(nums[0], nums[1])
    for i in range(2, len(nums)):
        prev2, prev1 = prev1, max(prev1, prev2 + nums[i])
    return prev1

6 House Robber II (#213) Medium

▶
PROBLEM
Same as House Robber, but houses are arranged in a circle. First and last houses are adjacent.
THE CHOICES
Same take-or-skip, but circular constraint. Can't rob both first and last. Run the linear version twice: once skipping first house, once skipping last. Answer = max of both.
def rob(nums):
    if len(nums) <= 2: return max(nums)
    def rob_line(arr):
        prev2, prev1 = arr[0], max(arr[0], arr[1])
        for i in range(2, len(arr)):
            prev2, prev1 = prev1, max(prev1, prev2 + arr[i])
        return prev1
    return max(rob_line(nums[1:]), rob_line(nums[:-1]))

7 Target Sum (#494) Medium

▶
PROBLEM
Given an array of integers and a target, assign + or - to each integer to make the sum equal target. Return the number of ways.
THE CHOICES
At each number: assign + or assign -. This is 0/1 knapsack (each number used once). Math trick: P - (total - P) = target means P = (total + target) / 2. Reduces to Count of Subsets with Sum.
def findTargetSumWays(nums, target):
    total = sum(nums)
    if (total + target) % 2 or abs(target) > total: return 0
    goal = (total + target) // 2
    dp = [0] * (goal + 1)
    dp[0] = 1
    for num in nums:
        for a in range(goal, num - 1, -1):
            dp[a] += dp[a - num]
    return dp[goal]

Unbounded Knapsack Items Reusable

8 Coin Change (#322) Medium

▶
PROBLEM
Given coins of different denominations and a total amount, return the fewest number of coins needed. Return -1 if impossible.
THE CHOICES
At each amount: try using each coin denomination. If coin fits, use it and solve for (amount - coin). Can reuse the same coin, so inner loop goes LEFT to RIGHT.
WHY IT'S DP
"Min coins for amount 7" might need "min coins for amount 4" (after using a 3-coin). "Min coins for amount 6" also needs "amount 4." Same subproblem.
def coinChange(coins, amount):
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0
    for coin in coins:
        for a in range(coin, amount + 1):
            dp[a] = min(dp[a], dp[a - coin] + 1)
    return dp[amount] if dp[amount] != float('inf') else -1

9 Coin Change II (#518) Medium

▶
PROBLEM
Given coins and an amount, return the number of combinations that make up that amount.
THE CHOICES
Same as Coin Change, but COUNT combinations instead of minimizing. += instead of min. Base case dp[0] = 1 (one way to make 0). Outer loop = coins ensures unique combos (avoids counting [1,2] and [2,1] separately).
def change(amount, coins):
    dp = [0] * (amount + 1)
    dp[0] = 1
    for coin in coins:
        for a in range(coin, amount + 1):
            dp[a] += dp[a - coin]
    return dp[amount]

10 Word Break (#139) Medium

▶
PROBLEM
Given a string s and a dictionary of words, determine if s can be segmented into a space-separated sequence of dictionary words.
THE CHOICES
At position i: try every split point j. If s[j:i] is a dictionary word AND dp[j] is True (prefix is valid), then dp[i] = True. Words are like coins (reusable), string length is the amount.
def wordBreak(s, wordDict):
    dp = [False] * (len(s) + 1)
    dp[0] = True
    words = set(wordDict)
    for i in range(1, len(s) + 1):
        for j in range(i):
            if dp[j] and s[j:i] in words:
                dp[i] = True
                break
    return dp[len(s)]

Palindrome Expand from Center

11 Longest Palindromic Substring (#5) Medium

▶
PROBLEM
Given a string s, return the longest palindromic substring in s.
THE CHOICES
At each center: expand outward. If s[l] == s[r], it's still a palindrome, keep expanding. If mismatch, stop. Try both odd-length (center on one char) and even-length (center between two chars).
def longestPalindrome(s):
    res = ""
    for center in range(len(s)):
        for l, r in [(center, center), (center, center + 1)]:
            while l >= 0 and r < len(s) and s[l] == s[r]:
                if r - l + 1 > len(res):
                    res = s[l:r+1]
                l -= 1; r += 1
    return res

12 Palindromic Substrings (#647) Medium

▶
PROBLEM
Given a string s, return the number of palindromic substrings in it.
THE CHOICES
Same expand-from-center approach. Instead of tracking the longest, just count every successful expansion as one more palindromic substring.
def countSubstrings(s):
    count = 0
    for center in range(len(s)):
        for l, r in [(center, center), (center, center + 1)]:
            while l >= 0 and r < len(s) and s[l] == s[r]:
                count += 1
                l -= 1; r += 1
    return count

LCS Two Sequences Compared

13 Longest Common Subsequence (#1143) Medium

▶
PROBLEM
Given two strings text1 and text2, return the length of their longest common subsequence.
THE CHOICES
At position (i, j): do the characters match? If YES: both advance, count it (diagonal + 1). If NO: skip one character from either string, take the better result (max of up, left).
WHY IT'S DP
2 changing variables (i and j) → 2D table. Base case (empty string) → first row/column = 0.
def longestCommonSubsequence(text1, text2):
    m, n = len(text1), len(text2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if text1[i-1] == text2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
    return dp[m][n]

14 Edit Distance (#72) Medium

▶
PROBLEM
Given two strings word1 and word2, return the minimum number of operations (insert, delete, replace) to convert word1 to word2.
THE CHOICES
At (i, j): characters match? Free, take diagonal. Don't match? Three choices: replace (diagonal + 1), delete from word1 (up + 1), insert into word1 (left + 1). Take the minimum.
def minDistance(word1, word2):
    m, n = len(word1), len(word2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(m + 1): dp[i][0] = i
    for j in range(n + 1): dp[0][j] = j
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if word1[i-1] == word2[j-1]:
                dp[i][j] = dp[i-1][j-1]
            else:
                dp[i][j] = 1 + min(dp[i-1][j-1], dp[i-1][j], dp[i][j-1])
    return dp[m][n]

15 Interleaving String (#97) Medium

▶
PROBLEM
Given strings s1, s2, and s3, determine if s3 is formed by interleaving s1 and s2.
THE CHOICES
At (i, j): does the next character in s3 come from s1 or s2? Check s3[i+j-1] against s1[i-1] (from above) or s2[j-1] (from left). Boolean 2D table.
def isInterleave(s1, s2, s3):
    m, n = len(s1), len(s2)
    if m + n != len(s3): return False
    dp = [[False] * (n + 1) for _ in range(m + 1)]
    dp[0][0] = True
    for i in range(1, m + 1):
        dp[i][0] = dp[i-1][0] and s1[i-1] == s3[i-1]
    for j in range(1, n + 1):
        dp[0][j] = dp[0][j-1] and s2[j-1] == s3[j-1]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            dp[i][j] = (dp[i-1][j] and s1[i-1] == s3[i+j-1]) or \
                        (dp[i][j-1] and s2[j-1] == s3[i+j-1])
    return dp[m][n]

16 Distinct Subsequences (#115) Hard

▶
PROBLEM
Given strings s and t, return the number of distinct subsequences of s which equals t.
THE CHOICES
At (i, j): always inherit from above (skip this char in s). If characters match, ALSO add the diagonal value (use this char). Count, not max.
def numDistinct(s, t):
    m, n = len(s), len(t)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(m + 1): dp[i][0] = 1
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            dp[i][j] = dp[i-1][j]
            if s[i-1] == t[j-1]:
                dp[i][j] += dp[i-1][j-1]
    return dp[m][n]

17 Regular Expression Matching (#10) Hard

▶
PROBLEM
Given a string s and a pattern p with '.' (any char) and '*' (zero or more of preceding), determine if the pattern matches the entire string.
THE CHOICES
At (i, j): if pattern char is '*', two choices: use zero of preceding (look 2 cols back) or use one more (look up, if char matches). If '.' or exact match, diagonal. Boolean 2D grid.
def isMatch(s, p):
    m, n = len(s), len(p)
    dp = [[False] * (n + 1) for _ in range(m + 1)]
    dp[0][0] = True
    for j in range(1, n + 1):
        if p[j-1] == '*':
            dp[0][j] = dp[0][j-2]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if p[j-1] == '*':
                dp[i][j] = dp[i][j-2]
                if p[j-2] == '.' or p[j-2] == s[i-1]:
                    dp[i][j] = dp[i][j] or dp[i-1][j]
            elif p[j-1] == '.' or p[j-1] == s[i-1]:
                dp[i][j] = dp[i-1][j-1]
    return dp[m][n]

18 Unique Paths (#62) Medium

▶
PROBLEM
A robot is on an m x n grid. It can only move right or down. How many unique paths exist from top-left to bottom-right?
THE CHOICES
At each cell: come from above or come from the left. dp[i][j] = dp[i-1][j] + dp[i][j-1]. Base: first row and first column all 1s (only one way to reach any edge cell).
def uniquePaths(m, n):
    dp = [[1] * n for _ in range(m)]
    for i in range(1, m):
        for j in range(1, n):
            dp[i][j] = dp[i-1][j] + dp[i][j-1]
    return dp[m-1][n-1]

State Machine Multiple States per Step

19 Best Time to Buy & Sell Stock with Cooldown (#309) Medium

▶
PROBLEM
Given an array of stock prices, find the maximum profit. After selling, you must wait one day before buying again (cooldown).
THE CHOICES
At each day, you're in one of three states: HOLD (bought, waiting), SOLD (just sold today), REST (cooling down or idle). Each state transitions based on the choice: hold = max(keep holding, buy from rest). sold = hold + price. rest = max(keep resting, cooldown from sold). Compute ALL new values simultaneously, then swap.
def maxProfit(prices):
    hold, sold, rest = -prices[0], 0, 0
    for price in prices[1:]:
        new_hold = max(hold, rest - price)
        new_sold = hold + price
        new_rest = max(rest, sold)
        hold, sold, rest = new_hold, new_sold, new_rest
    return max(sold, rest)
Why simultaneous swap: If you update hold first and then use it to compute sold, you're using today's buy decision to sell today. That's time travel. Compute ALL new values first, THEN swap.

20 Longest Increasing Subsequence (#300) Medium

▶
PROBLEM
Given an integer array nums, return the length of the longest strictly increasing subsequence.
THE CHOICES
At position i: for each previous position j where nums[j] < nums[i], you can extend that subsequence by 1. dp[i] = max(dp[j] + 1) for all valid j. Answer = max of entire dp array (the LIS can end anywhere).
def lengthOfLIS(nums):
    dp = [1] * len(nums)
    for i in range(1, len(nums)):
        for j in range(i):
            if nums[j] < nums[i]:
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp)

Interval Process a Range

21 Burst Balloons (#312) Hard

▶
PROBLEM
Given n balloons with values, burst them to maximize coins. Bursting balloon i gives nums[left] * nums[i] * nums[right]. Return maximum coins.
THE CHOICES
Within interval [l, r]: which balloon pops LAST? Think backwards. The last balloon to pop in this range sees boundaries l and r as its neighbors. Try each k in [l+1, r-1] as the last pop. dp[l][r] = max over all k of (dp[l][k] + dp[k][r] + nums[l]*nums[k]*nums[r]).
WHY IT'S DP
Overlapping subintervals. dp[0][3] and dp[2][5] both need dp[2][3]. Same range, same answer. Also: iterate by interval LENGTH (small to large) so smaller subproblems are solved first.
def maxCoins(nums):
    nums = [1] + nums + [1]
    n = len(nums)
    dp = [[0] * n for _ in range(n)]
    for length in range(2, n):
        for l in range(n - length):
            r = l + length
            for k in range(l + 1, r):
                dp[l][r] = max(dp[l][r],
                    dp[l][k] + dp[k][r] + nums[l] * nums[k] * nums[r])
    return dp[0][n-1]

Quiz

Click each card to reveal the answer.

1. What is Aditya Verma's first step for any DP problem?
Find the CHOICES. At each item/position/step, what can you do? Take or skip? Match or insert? The choice diagram IS the recursion. The code writes itself from the choices.
2. How do you know a problem is DP (not just recursion)?
Overlapping subproblems. Draw the recursive tree. If the SAME subproblem (same inputs) appears in DIFFERENT branches, it's DP. Same inputs, same answer, why solve it twice?
3. How do you determine the table dimensions?
Count the changing variables. Look at the recursive function's parameters. Which ones change across calls? 1 variable → 1D array. 2 variables → 2D table. The table shape comes directly from the recursion, not from guessing.
4. How do you initialize the table?
From the recursive base case. Whatever the recursion returns at the base (n==0 or W==0), fill that into the corresponding row/column of the table. Recursive base case = table initialization.
5. In 0/1 Knapsack, why does the 1D inner loop go RIGHT to LEFT?
To prevent using the same item twice. Right to left ensures dp[j-num] still holds the value from BEFORE this item was considered. Left to right would let earlier updates affect later cells, effectively reusing the item (that's Unbounded Knapsack).
6. What is the relationship between memoization and tabulation?
Same logic, different direction. Memoization = top-down recursion + cache (3 extra lines). Tabulation = bottom-up loops + table (replace recursion with loops). The formula in each cell is identical to the recursive formula. Tabulation avoids function call overhead and stack overflow risk.
7. How does Target Sum (#494) reduce to a knapsack problem?
Math trick. Split numbers into P (positive set) and N (negative set). P - N = target, and P + N = totalSum. So P = (totalSum + target) / 2. Now it's: "count subsets summing to P." That's Count of Subsets with Sum, a direct child of 0/1 Knapsack.
8. What family does Coin Change belong to, and how is it different from 0/1 Knapsack?
Unbounded Knapsack. Coins can be reused (take the same coin multiple times). In 0/1, each item is used at most once. The code difference: 0/1 inner loop goes RIGHT to LEFT. Unbounded goes LEFT to RIGHT. In 2D table: 0/1 looks at row above (dp[i-1]). Unbounded looks at same row (dp[i]).
9. In Buy & Sell with Cooldown, why must you swap all state variables simultaneously?
To avoid time travel. If you update hold first (buying today) then use the updated hold to compute sold (selling today), you've bought and sold on the same day. Compute ALL new values from yesterday's state, THEN swap all at once.
10. What makes Burst Balloons an interval DP problem?
You process a range, choosing where to split. dp[l][r] represents a range/interval, not two sequence positions. You iterate by interval LENGTH (small first, building to larger). At each interval, you choose which balloon pops LAST (think backwards). This "last to process" trick is the hallmark of interval DP / Matrix Chain Multiplication.
