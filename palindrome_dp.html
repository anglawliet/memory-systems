The Problem

Palindromic Substrings (LeetCode #647)

Given a string, count how many substrings are palindromes. A palindrome reads the same forwards and backwards.

a a b a a

Palindromic substrings:

"a" x5 "aa" x2 "aba" "aabaa"
9 palindromic substrings

0 Is This a DP Problem?

What is the problem asking me to compute?

Count every substring that reads the same forwards and backwards. For a string of length n, there are n(n+1)/2 substrings to check.

Why doesn't greedy work?

There's no greedy strategy here. I can't pick a starting point and greedily expand. I have to check every possible substring independently. No shortcut lets me skip substrings.

Why would brute force create overlapping subproblems?

Checking "aabaa": is it a palindrome?
→ Ends match ('a' == 'a'). Check the inside: is "aba" a palindrome?

But "aba" is also a substring I need to check independently.
Same question, computed twice. That's an overlapping subproblem.

Which family?

String DP. I'm checking a property of a range of characters. The result for a longer range depends on the result for a shorter inner range.

1 The Recursive Question

Before writing any recursion, answer this in plain English:

"Is the substring text[left..right] a palindrome?"

This function answers exactly one question. It takes two positions (left and right) and returns True or False for that specific substring.

The counting happens outside. I check every (left, right) pair and count how many return True. The recursive function only answers: is this one substring a palindrome?

2 Discover the Base Cases

Do not derive base cases from the recurrence. Instead ask:

"If I keep making decisions, when must I eventually stop?"

The recursive function peels off one character from each end and checks the inside. Each call shrinks the substring by 2. Eventually the substring becomes too small to peel further. That's when I stop.

STOP: Single character (left == right)
b
What situation have I reached? One character left. Nothing to compare it against.
Why can't I continue? Peeling requires two ends. One character has no "other end."
What should this return? True.
Why True? "b" reversed is "b". A single character reads the same in both directions. That's the definition of a palindrome.
STOP: Empty substring (left > right)
(nothing here)
What situation have I reached? Left pointer has crossed past right. The substring is empty.
When does this happen? After peeling both ends from a length-2 palindrome. Example: "aa" has matching ends. Peel both: left becomes 1, right becomes 0. Empty.
What should this return? True.
Why True and not False? All the outer layers have already confirmed matching. An empty center doesn't break anything. It means every pair was checked and passed. Returning False here would incorrectly reject "aa".
Why are these the only two stops? Any substring with 2+ characters has two ends to compare. The function always has work to do until the substring shrinks to 0 or 1 characters.

3 Discover the Choices

I'm inside one recursive call. The substring has at least 2 characters (base cases didn't trigger). Now:

What is my current situation?

I'm looking at text[left..right]. I want to know: is this a palindrome?

a a b a a
I'm pointing at the first character (left) and the last character (right).

What am I allowed to do?

The string is fixed. I can't skip characters, swap them, insert new ones, or rearrange anything. I can only observe.

So the question isn't "what action should I take?" but "what should I check?"

What am I forbidden from doing?

Modifying the string. This isn't an optimization where I choose between options. This is a verification where I inspect the data.

Why are these the only legal actions?

THE CHECK: Do the two end characters match?
A palindrome reads the same forwards and backwards. That means the first character must equal the last character. If they don't match, nothing inside can fix it. This is the cheapest and most decisive single check I can make.

Could I check the middle first? I could, but if the ends don't match, I wasted work on the middle. Checking ends first eliminates the most work on failure.

Could I check two random positions? That tells me nothing useful. The ends are the only positions guaranteed to matter for a palindrome.

Have I missed any checks? No. One check, two outcomes.

4 Explain Each Outcome

OUTCOME 1: The ends match (text[left] == text[right])
a a b a a
What am I doing? Confirming the outer pair is valid.
Why is this a legal move? A palindrome requires first == last. They do match, so this layer passes.
What changes immediately? The outer pair is handled. My focus shrinks to the inner substring, one character shorter on each side.
What stays unchanged? The question is identical: "is this (smaller) substring a palindrome?"
What remains to solve? Check the inner substring. Same problem, smaller input. is_palindrome(left+1, right-1)
OUTCOME 2: The ends don't match (text[left] != text[right])
a b c
What am I doing? Observing that the outer characters differ.
Why is this a legal move? It's an observation, not a choice.
What changes immediately? Nothing. I stop.
What stays unchanged? Nothing matters anymore.
What remains to solve? Nothing. Return False. The inside is irrelevant.

The Choice Diagram

is_palindrome(left, right)   [base cases already handled]
        │
  Do text[left] and text[right] match?
        │
   ┌────┴────┐
   │         │
  YES        NO
   │         │
   │     Return False.
   │     (Ends differ, game over.)
   │
   ▼
  Peel both ends off.
  Return is_palindrome(left+1, right-1)

The combine step: ends_match AND is_palindrome(inside). Both must be true. There's no max or min here. If the ends match but the inside isn't a palindrome, the whole thing fails.

5 Discover the State

Ask: what information must I know to uniquely describe the remaining problem?

Consider every piece of information that changes between calls:

Candidate: left (starting position)
Why do I need it? Different starting positions give different substrings. text[0..4] is "aabaa", text[1..4] is "abaa". Different strings, different answers.
What if I remove it? "Is text[?..4] a palindrome?" is ambiguous. Five substrings end at position 4. I can't tell which one I'm checking.
Candidate: right (ending position)
Why do I need it? Different ending positions give different substrings. text[0..4] is "aabaa", text[0..2] is "aab". Different answers.
What if I remove it? "Is text[0..?] a palindrome?" is ambiguous. Same problem.
Candidate: the text itself
Does it change between calls? No. The text is constant. I never modify it.
Verdict: Not part of the state. It's a global constant.
State = (left, right)
Two integers. This uniquely identifies "is text[left..right] a palindrome?"

6 State Invariant

Before writing the recurrence, define what the recursive function promises:

is_palindrome(left, right)
"I promise to determine whether text[left..right] is a palindrome. I don't need anything outside this range. Everything outside [left, right] is either already confirmed or irrelevant."

Does every recursive call preserve this?

The only recursive call: is_palindrome(left+1, right-1)

This asks about text[left+1..right-1], which is a subset of [left, right]. The inner call never looks outside the original range. Invariant preserved.

Why this matters: When I call is_palindrome(left+1, right-1), I've already confirmed text[left] == text[right]. The outer pair is handled. The inner call only needs to worry about the inside. No information leaks in either direction.

7 Derive the Transition

For every transition, explain: what action, what cost, which variables change, which stay, and why.

MATCH: text[left] == text[right]
Action: Confirmed the outer pair matches. Peel them off.
Cost/reward: None. A match doesn't add to a count. It just means this layer is valid.
State changes:
left → left+1: text[left] confirmed. Move inward from the left. This character is consumed.
right → right-1: text[right] confirmed. Move inward from the right. This character is consumed.
Why do BOTH change? A palindrome is symmetric. Confirming a pair means both ends are done simultaneously. You can't confirm just one end of a pair.
Remaining subproblem: is_palindrome(left+1, right-1)
NO MATCH: text[left] != text[right]
Action: Observed that the outer characters differ.
Result: Return False immediately. No recursion needed.
Why no recursion? If the outermost characters differ, the string cannot be a palindrome. No inner check can change that. The answer is definitively False.

8 Derive the Recurrence

Now the recurrence writes itself from what I derived. No step was skipped.

is_palindrome(left, right) =
    True                                    if left >= right
    False                                   if text[left] != text[right]
    is_palindrome(left+1, right-1)          if text[left] == text[right]

For counting: count = sum of is_palindrome(left, right) for all 0 <= left <= right < n

The code

def is_palindrome(text, left, right):
    if left >= right:
        return True
    if text[left] != text[right]:
        return False
    return is_palindrome(text, left + 1, right - 1)

def count_palindromes(text):
    count = 0
    for left in range(len(text)):
        for right in range(left, len(text)):
            if is_palindrome(text, left, right):
                count += 1
    return count

This is correct but slow. For each of n² substrings, the recursive check can take O(n). Total: O(n³). We'll fix this with memoization.

9 Memoization

Why does repeated work occur?

When checking all substrings, different outer substrings share inner subproblems:

Checking all substrings of "aabaa":

is_palindrome(0, 4) "aabaa"
  calls is_palindrome(1, 3) "aba"  ─ ─ ─ ┐
    calls is_palindrome(2, 2) "b"         │
                                          │ SAME!
Checking substring "aba" directly:        │
is_palindrome(1, 3) "aba"  ─ ─ ─ ─ ─ ─ ─ ┘
  calls is_palindrome(2, 2) "b"

Which states repeat?

Any (left, right) that is both a substring we check directly AND an inner subproblem of a longer substring. The overlap is structural, not accidental.

How memoization removes repetition

Store the result for each (left, right). Before computing, check the cache. Cache size: at most n² entries.

def is_palindrome(text, left, right, cache):
    if left >= right:
        return True
    if (left, right) in cache:
        return cache[(left, right)]

    if text[left] != text[right]:
        result = False
    else:
        result = is_palindrome(text, left + 1, right - 1, cache)

    cache[(left, right)] = result
    return result

def count_palindromes(text):
    cache = {}
    count = 0
    for left in range(len(text)):
        for right in range(left, len(text)):
            if is_palindrome(text, left, right, cache):
                count += 1
    return count

Store True/False for this range

Two state variables. At most n² entries.

10 Tabulation

Why the table dimensions come from the state

State = (left, right). Two variables, each ranging from 0 to n-1. That gives a 2D table.

is_pal[left][right] = True if text[left..right] is a palindrome.

Why the iteration order works

is_pal[left][right] depends on is_pal[left+1][right-1], which is a shorter substring. If I fill by increasing substring length, every dependency is already computed when I need it.

For "aab":

0 'a'1 'a'2 'b'
0 'a'TTF
1 'a'TF
2 'b'T

Only the upper triangle matters (left <= right). Count the T's: 4 palindromic substrings.

Why every dependency has already been computed

Length 1: every character
is_pal[0][0] = T, is_pal[1][1] = T, is_pal[2][2] = T
Single characters are always palindromes. No dependencies. Count = 3.
Length 2: check if both chars match
text[0]='a' == text[1]='a'? YES. is_pal[0][1] = T
text[1]='a' == text[2]='b'? NO. is_pal[1][2] = F
For length 2, the "inner" substring is empty (base case True). So only the end-match matters. Count = 4.
Length 3: check ends + inner palindrome
text[0]='a' == text[2]='b'? NO. is_pal[0][2] = F
Ends don't match, no need to check inside. Count stays 4.

The Tabulation Code

def count_palindromes(text):
    n = len(text)
    is_pal = [[False] * n for _ in range(n)]
    count = 0

    for i in range(n):
        is_pal[i][i] = True
        count += 1

    for i in range(n - 1):
        if text[i] == text[i + 1]:
            is_pal[i][i + 1] = True
            count += 1

    for length in range(3, n + 1):
        for left in range(n - length + 1):
            right = left + length - 1
            if text[left] == text[right] and is_pal[left + 1][right - 1]:
                is_pal[left][right] = True
                count += 1

    return count

11 Space Optimization

Which previous states are actually needed?

is_pal[left][right] depends on is_pal[left+1][right-1] (one row down, one column left in the table). This diagonal dependency means we can't easily reduce to a single row like in knapsack.

Why older states can be discarded

The 2D table approach uses O(n²) space. An alternative, the expand-around-center approach, achieves O(1) space:

def count_palindromes(text):
    count = 0
    for center in range(len(text)):
        count += expand(text, center, center)
        count += expand(text, center, center + 1)
    return count

def expand(text, left, right):
    count = 0
    while left >= 0 and right < len(text) and text[left] == text[right]:
        count += 1
        left -= 1
        right += 1
    return count

This is a different algorithm (expand outward instead of check inward), not a direct optimization of the table. But it gives O(n²) time and O(1) space.

12 Pattern Recognition

What clues suggested this DP pattern?

"Is substring X a palindrome?" → Checking a property of a range of characters → state = (left, right).
Result for longer range depends on shorter range → Overlapping subproblems → memoize or tabulate.
Fill by increasing length → Longer ranges depend on shorter ones → process short to long.

What should I immediately think when I see a similar problem?

"Two pointers inward, check ends, cache the range." Any problem asking about a property of a substring range likely follows this shape.

What generalizes to future problems?

State = (left, right) for any range-checking problem
Fill order = by increasing length when longer depends on shorter
The problem definition tells you the check. The check tells you the outcomes. The outcomes tell you the recursion.

13 Common Mistakes

Wrong base case: forgetting left > right
Only handling left == right (single char) but not left > right (empty). This breaks on even-length palindromes like "aa", where peeling both ends gives left=1, right=0.
How to detect: test with "aa". If it returns False, the empty base case is missing.
Wrong return for empty: returning False instead of True
If left > right returns False, then "aa" would fail because the inner check (empty) returns False, even though the ends matched.
How to detect: trace "aa" by hand. left=0, right=1. Ends match. Check is_palindrome(1, 0). What does it return?
Wrong fill order: filling row by row instead of by length
is_pal[0][4] depends on is_pal[1][3]. If filling row 0 first, row 1 hasn't been computed yet. Fill by length instead: length 1, then 2, then 3, etc.
How to detect: check if is_pal[left+1][right-1] is still at its initial value (False) when you need it.
Checking middle before ends
If you recursively check the inside first, then compare ends, you waste work. When the ends don't match, all inner work was pointless. Always check ends first.
How to detect: performance issue. Code is correct but slow on strings where most substrings are NOT palindromes.

1 Longest Palindromic Substring

▶
LEETCODE #5
Given a string, return the longest palindromic substring. Same table, but instead of counting, track the longest one found.
Example:
"babad"

All palindromic substrings:
"b", "a", "b", "a", "d" (each single char, length 1)
"bab" (length 3, palindrome)
"aba" (length 3, palindrome)

Answer: "bab" (or "aba", both are valid since both have length 3).
WHAT CHANGES FROM THE PARENT
Classification: Same. Still string DP, same overlapping subproblems.
Recursive question: Same. Still "is text[left..right] a palindrome?"
Base cases, choices, state, transitions: All identical.
Only the outer loop changes: Instead of count += 1, track if this palindrome is longer than the current best.

Recursion

def longest_palindrome(text):
    cache = {}
    best_start = 0
    best_length = 1

    for left in range(len(text)):
        for right in range(left, len(text)):
            if is_palindrome(text, left, right, cache):
                if right - left + 1 > best_length:
                    best_start = left
                    best_length = right - left + 1

    return text[best_start:best_start + best_length]

Uses the same is_palindrome with memoization from the parent.

Tabulation

def longest_palindrome(text):
    n = len(text)
    is_pal = [[False] * n for _ in range(n)]
    start = 0
    max_length = 1

    for i in range(n):
        is_pal[i][i] = True

    for i in range(n - 1):
        if text[i] == text[i + 1]:
            is_pal[i][i + 1] = True
            start = i
            max_length = 2

    for length in range(3, n + 1):
        for left in range(n - length + 1):
            right = left + length - 1
            if text[left] == text[right] and is_pal[left + 1][right - 1]:
                is_pal[left][right] = True
                if length > max_length:
                    start = left
                    max_length = length

    return text[start:start + max_length]

The Pattern

2D table, fill by substring length

Palindromic Substrings
is_pal[l][r] = match AND is_pal[l+1][r-1]
Operation: count True cells
Fill order: by substring length (1, 2, 3, ...)
Longest Palindromic
is_pal[l][r] = match AND is_pal[l+1][r-1]
Operation: track max length
Fill order: same (by length)
Palindrome DP in one sentence: a substring is a palindrome if its ends match AND its inner part is already confirmed as a palindrome. Build from the inside out.
