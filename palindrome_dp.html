The Problem

Palindromic Substrings (LeetCode #647)

Given a string text, count how many of its substrings are palindromes.

textcountwhy
"aab"4a, a, b, aa
"abc"3a, b, c
"aaa"6a, a, a, aa, aa, aaa
"a"1a
"aabaa"95 single + aa + aa + aba + aabaa

1 What Is It Really Asking?

For every possible (left, right) pair, ask one yes/no question: is text[left..right] a palindrome? Count the yeses.

One string, not two. The state lives inside a single string, not across two.

2 What Would I Naturally Try?

For every substring, reverse it and compare to the original.

for left in range(n):
    for right in range(left, n):
        sub = text[left:right+1]
        if sub == sub[::-1]:
            count += 1

O(n²) substrings, each reversed and compared in O(n) → O(n³).

3 Where Does That Fail?

Checking "aabaa" re-verifies the inner "aba" from scratch, even though "aba" is checked again on its own as a separate substring.

Wasted work: the same inner range gets re-verified by every outer range that contains it.

4 Frozen at (left, right)

I'm mid-check on text[left..right]. Everything outside this range is irrelevant right now.

What's the one question I must answer to move forward? Do the two end characters match?

5 What Can I Do?

Only one legal move: compare text[left] to text[right]. No skipping, no swapping, just observing.

6 Why Only These?

A palindrome's definition requires first == last. That's not a choice I'm making, it's a fact I'm checking. One check, two outcomes.

7 Watch Each Choice Play Out

Match
Ends confirmed. Check the inside: is_palindrome(left+1, right-1).
No match
Ends differ, game over. return False immediately, no recursion.

8 What Must I Remember? (The State)

State = (left, right)
The text itself never changes, so it's not part of the state.

9 What Do the Variables Mean?

left
Start of the substring being checked.
right
End of the substring being checked.

10 What Does the Function Promise?

is_palindrome(left, right) returns True if text[left..right] reads the same forwards and backwards.

This is verification, not optimization. There's no "best" answer to maximize, just true or false.

11 When Must We Stop? (Base Cases)

left == right
Single character. Reads the same either way. Return True.
left > right
Empty inside. All outer layers already matched. Return True.

12 What Smaller Problem Remains? (Transitions)

match
left+1, right-1. Both ends consumed, shrink inward.
no match
return False. No smaller problem to solve.

13 How Do We Combine Results?

Both the outer match and the inner result must hold. Not max, not min, not addition.

ends_match AND is_palindrome(inside). One False anywhere kills the whole answer.

15 Brute-Force Code

def is_palindrome(text, left, right):
    if left >= right:
        return True
    if text[left] != text[right]:
        return False
    return is_palindrome(text, left + 1, right - 1)

def count_palindromic_substrings(text):
    n = len(text)
    count = 0
    for left in range(n):
        for right in range(left, n):
            if is_palindrome(text, left, right):
                count += 1
    return count

18 Why Is It Slow?

Checking (0,4) on "aabaa" verifies (1,3). But (1,3) is also checked directly by the outer double loop. Same range, computed twice.

19 Memoization

Cache key: (left, right). Cache value: True/False. At most n² entries.

def is_palindrome(text, left, right, cache):
    if (left, right) in cache:
        return cache[(left, right)]
    if left >= right:
        result = True
    elif text[left] != text[right]:
        result = False
    else:
        result = is_palindrome(text, left + 1, right - 1, cache)
    cache[(left, right)] = result
    return result

20 Tabulation

table[left][right] depends on table[left+1][right-1], a shorter range. So fill by increasing substring length, not row by row.

n = len(text)
table = [[False] * n for _ in range(n)]

for length in range(1, n + 1):
    for left in range(n - length + 1):
        right = left + length - 1
        if length == 1:
            table[left][right] = True
        elif length == 2:
            table[left][right] = text[left] == text[right]
        else:
            table[left][right] = text[left] == text[right] and table[left+1][right-1]
Why by length? Row-by-row order would try to read table[left+1][right-1] before it's filled, since that cell can sit in a later row.

21 Space Optimization

Drop the O(n²) table entirely. Expand from every center outward instead: n odd centers plus n-1 even centers (between-character gaps).

def count_palindromic_substrings(text):
    n, count = len(text), 0
    def expand(left, right):
        nonlocal count
        while left >= 0 and right < n and text[left] == text[right]:
            count += 1
            left -= 1
            right += 1
    for center in range(n):
        expand(center, center)       # odd length
        expand(center, center + 1)   # even length
    return count
O(n²) time, O(1) space. No table, no cache.

22 Common Mistakes

Returning False for the empty base case. left > right means everything outer already matched; it must be True.
Using OR instead of AND. Both the end match and the inner result are required, not either one.
Tabulating row by row. table[left+1][right-1] may live in a later row; fill by length instead.

23 Pattern Recognition

When I see "one string" + "is this range valid?" I should consider a (left, right) verification with AND, not max/min.

24 Rediscover It Six Months Later

1"One string, checking a range. Naive: reverse and compare, O(n³)."
2"Frozen at (left, right): do the ends match?"
3"Match: check inside. No match: False immediately. State = (left, right)."
4"Base cases: single char and empty are both True. AND combines the layers."
5"Overlapping ranges → cache. Fill table by length, not row. Or expand from centers for O(1) space."

Brute-force (with memoization)

def longest_palindrome(text):
    cache = {}
    start, max_length = 0, 1

    for left in range(len(text)):
        for right in range(left, len(text)):
            if is_palindrome(text, left, right, cache):
                length = right - left + 1
                if length > max_length:
                    start, max_length = left, length

    return text[start:start + max_length]

Tabulation

def longest_palindrome(text):
    n = len(text)
    is_pal = [[False] * n for _ in range(n)]
    start, max_length = 0, 1

    for i in range(n):
        is_pal[i][i] = True

    for i in range(n - 1):
        if text[i] == text[i + 1]:
            is_pal[i][i + 1] = True
            start, max_length = i, 2

    for length in range(3, n + 1):
        for left in range(n - length + 1):
            right = left + length - 1
            if text[left] == text[right] and is_pal[left + 1][right - 1]:
                is_pal[left][right] = True
                if length > max_length:
                    start, max_length = left, length

    return text[start:start + max_length]
Key insight: build the exact same table. Just remember the biggest True cell instead of counting all of them.

The Pattern

2D table, fill by substring length

Palindromic Substrings
is_pal[l][r] = match AND is_pal[l+1][r-1]
Operation: count True cells
Fill order: by substring length
Longest Palindromic
is_pal[l][r] = match AND is_pal[l+1][r-1]
Operation: track max length
Fill order: same (by length)
Palindrome DP in one sentence: a substring is a palindrome if its ends match AND its inner part is already confirmed. Build from the inside out.
