The Problem

Climbing Stairs

🧗
Maya
Rock climber. Chalk bag on her hip. Writes numbers on each step.
The Question
A staircase has 6 steps. At each step, Maya can climb 1 step or 2 steps. How many different ways can she reach the top?
Why start here? This problem has ONE changing variable (which step you're on). That means the table is just one array. No rows and columns to worry about. Learn tabulation here, then add the second dimension in knapsack.

Step 1: What Are My Choices?

At each step: climb 1 or climb 2

THE CHOICE DIAGRAM
Standing at step remaining. How do I get here?

I could have come from 1 step below (climbed 1)
I could have come from 2 steps below (climbed 2)

So: ways to reach this step = ways to reach (step - 1) + ways to reach (step - 2)

Two choices at each step. Each choice leads to a smaller problem (fewer steps remaining). That's exactly the pattern for recursion.

Step 2: Choices → Recursion

The code writes itself from the choices

def count_ways(remaining):
    if remaining == 0: return 1
    if remaining == 1: return 1
    return count_ways(remaining - 1) + count_ways(remaining - 2)
From the choices
count_ways(remaining - 1) → came from 1 below
count_ways(remaining - 2) → came from 2 below
+ → add them (we want TOTAL ways, not the best)
Base cases
remaining == 0 → already at the top. 1 way (do nothing).
remaining == 1 → 1 step left. 1 way (climb 1).
Notice: Knapsack used max(grab, skip) because it wanted the BEST value. Stairs uses + because it wants the TOTAL count of ways. Different question, same structure.

Step 3: Draw the Tree, Spot the Overlap

count_ways(4) expanded

count_ways(4)
├── count_ways(3)                         # climb 1 from step 3
│   ├── count_ways(2)  ─ ─ ─ ┐           # climb 1 from step 2
│   │   ├── count_ways(1) = 1 │
│   │   └── count_ways(0) = 1 │  SAME!
│   └── count_ways(1) = 1     │
└── count_ways(2)  ─ ─ ─ ─ ─ ┘           # climb 2 from step 2
    ├── count_ways(1) = 1
    └── count_ways(0) = 1
count_ways(2) appears TWICE
Both times the answer is 2. Same question, same answer. Solved twice without caching.

A problem is DP when:

1.
You make CHOICES (climb 1 or climb 2)
2.
The SAME subproblem appears MULTIPLE times in the tree
3.
Each subproblem has the SAME answer every time

Step 4: Memoize (3 extra lines)

Same code, just cache the answers

def count_ways(remaining, memo={}):
    if remaining in memo: return memo[remaining]      # CHECK: already solved?
    if remaining == 0: return 1
    if remaining == 1: return 1
    result = count_ways(remaining - 1, memo) + count_ways(remaining - 2, memo)
    memo[remaining] = result                           # STORE the answer
    return result
Without cache: O(2remaining)
Every branch explored, including duplicates.
With cache: O(remaining)
Each value of remaining solved at most once.

Step 5: From Recursion to Table

This is the section that matters. Everything above (choices, recursion, tree, memo) you already know. The table is what trips people up. We'll go slow, one question at a time.

Q: Why an array? Why not a table with rows and columns?

Look at your recursive function:

def count_ways(remaining):

How many parameters change across recursive calls?

remaining
Goes down by 1 or 2 each call
CHANGES ✓

1 changing variable → 1D array. That's it.

Compare: knapsack had 2 changing variables (count and bag_limit), so it needed a 2D table. Stairs has just 1, so a simple array is enough.

The rule: Count the parameters that change across recursive calls. That count = number of dimensions.
1 variable → 1D array. 2 variables → 2D table. 3 variables → 3D (rare). Always.

Q: How do I fill the rest? Which direction?

The recursive formula:

count_ways(remaining) = count_ways(remaining - 1) + count_ways(remaining - 2)

In table language:

ways[step] = ways[step - 1] + ways[step - 2]

Each cell needs the two cells before it. So fill left to right, starting from step 2 (the first cell after the base cases).

Where does each piece come from?

ways[step - 1] = the cell one spot to the left (reached this step by climbing 1)
ways[step - 2] = the cell two spots to the left (reached this step by climbing 2)
+ = add them (total number of ways)

This is why we fill left to right: when we get to step 3, steps 1 and 2 are already filled. When we get to step 4, steps 2 and 3 are already filled. Each cell can always look back at cells that already have values.

The Tabulation Code

Every line maps to something we just did

def count_ways(steps_to_top):
    ways = [0] * (steps_to_top + 1)        # empty array, one cell per step

    ways[0] = 1                             # base case: 1 way to stand at ground
    ways[1] = 1                             # base case: 1 way to reach step 1

    for step in range(2, steps_to_top + 1): # fill left to right, starting at step 2
        ways[step] = ways[step - 1] + ways[step - 2]   # look back 1 + look back 2

    return ways[steps_to_top]               # last cell = the answer

The Whole Picture: Same Logic, Three Forms

Recursion → Memoization → Tabulation

RECURSION (correct but slow, O(2n))
def count_ways(remaining):
    if remaining == 0: return 1
    if remaining == 1: return 1
    return count_ways(remaining - 1) + count_ways(remaining - 2)
MEMOIZATION (add a cache, O(n))
def count_ways(remaining, memo={}):
    if remaining in memo: return memo[remaining]
    if remaining == 0: return 1
    if remaining == 1: return 1
    result = count_ways(remaining - 1, memo) + count_ways(remaining - 2, memo)
    memo[remaining] = result
    return result
TABULATION (no recursion, O(n))
def count_ways(steps_to_top):
    ways = [0] * (steps_to_top + 1)
    ways[0] = 1
    ways[1] = 1
    for step in range(2, steps_to_top + 1):
        ways[step] = ways[step - 1] + ways[step - 2]
    return ways[steps_to_top]

Same answer (13 for 6 steps). Recursion is the clearest to write. Memoization makes it fast. Tabulation removes the recursion entirely.

The Bridge to Knapsack

You just learned tabulation. Knapsack is the same idea, one more dimension.

Staircase (1D)
1 changing variable: remaining
Table shape: 1D array
Each cell: ways[step]
Looks at: the 2 cells to the left
Base cases: first 2 cells
Answer: last cell
Knapsack (2D)
2 changing variables: count, bag_limit
Table shape: 2D table (rows × columns)
Each cell: table[row][cap]
Looks at: the row above
Base cases: first row and first column
Answer: bottom-right cell
The pattern is identical:
1. Count changing variables → that's your dimensions
2. Base case in recursion → fill the edges of the array/table
3. Recursive formula → cell formula (same math, reads from the table)
4. Fill in order so every cell you need is already computed
5. The answer is at the end (last cell, or bottom-right corner)

The Linear DP Family

Same pattern, small tweaks

Every problem below uses the same 1D tabulation structure. The only thing that changes is what each cell stores and which cells it looks back at.

Climbing Stairs (#70)
ways[step] = ways[step - 1] + ways[step - 2]
Cell stores: number of ways. Looks back: 2 cells. Operation: add.
Min Cost Climbing Stairs (#746)
cost_to[step] = min(cost_to[step-1] + cost[step-1], cost_to[step-2] + cost[step-2])
Cell stores: minimum cost. Looks back: 2 cells. Operation: min (cheapest path).
House Robber (#198)
best[house] = max(best[house-1], best[house-2] + money[house])
Cell stores: max money. Looks back: 2 cells. Operation: max (rob or skip, like knapsack!).
Decode Ways (#91)
ways[i] = (ways[i-1] if valid single) + (ways[i-2] if valid pair)
Cell stores: number of ways. Looks back: 1 or 2 cells (conditional). Operation: add.
