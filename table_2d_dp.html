2D Table DP

Two sequences, one grid. Match on the diagonal, else take the best neighbor.

← Palindrome State Machine → Knapsack

The Problem

Longest Common Subsequence (LeetCode #1143)

Given two strings, find the length of their longest common subsequence. A subsequence keeps the order but can skip characters.

text1
"abcde"
text2
"ace"
LCS = "ace", length = 3

Both strings contain 'a', 'c', 'e' in order. That's the longest common subsequence.

text1 = "abc", text2 = "abc" → 3 — Identical strings. Every character matches diagonally.
text1 = "abc", text2 = "def" → 0 — No common characters. Every cell uses max(up, left).

Step 1: Discovering the Choices

What's my situation?

I have two strings. I'm pointing at one character in each: text1[i] and text2[j]. I want to find the longest sequence of characters that appears in both strings (in order, but not necessarily next to each other).

text1
a b c d e
i is pointing here
text2
a c e
j is pointing here

I need to decide: what do I do with these two characters I'm looking at right now?

What can I do right now?

I'm comparing two characters. The most natural first check: are they the same?

THE KEY QUESTION: "Do these two characters match?"
If they match: I found a common character. Should I use it? Yes, absolutely. If two characters are the same and in position, they're part of (or could be part of) the common subsequence. There's no reason to skip a matching pair.
If they don't match: At least one of these characters isn't useful right now. But which one? I don't know. Maybe text1[i] matches something later in text2. Maybe text2[j] matches something later in text1. I have to try both possibilities.
Could I skip both at once? No. That would throw away a character that might have matched something later. Skipping both is always worse than or equal to skipping just one.

What happens in each outcome?

OUTCOME 1: text1[i] == text2[j] (Match)
text1: a b c d e    text2: a c e
What am I choosing? Take this matching character as part of the LCS.
What changes immediately? LCS length grows by 1. Both characters are consumed (used up).
What stays the same? The remaining characters in both strings. The question is the same: "what's the LCS of what's left?"
What new situation does this create? I'm now pointing at text1[i+1] and text2[j+1]. Same problem, smaller input.
Call: 1 + lcs(i+1, j+1)
OUTCOME 2: text1[i] != text2[j] (No Match)
text1: b c d e    text2: c e

They don't match. I need to move past one of them, but which? I don't know. Try both:

Skip text1[i]
Why? Maybe text1[i] doesn't appear in text2 at all. Move past it.

What changes? i advances. j stays (text2[j] still needs a match).

Call: lcs(i+1, j)
Skip text2[j]
Why? Maybe text2[j] doesn't match anything left in text1. Move past it.

What changes? j advances. i stays (text1[i] still needs a match).

Call: lcs(i, j+1)
Decision: max(skip_first, skip_second). Try both, keep whichever gives a longer subsequence.

The reusable principle

The choices came from one question: "do these two characters match?" That's the most natural first check when comparing two sequences. The match case is free (no decision to make). The no-match case forces a decision (which to skip), so you try both.

For any two-sequence DP problem, ask: "What can I do with the two elements I'm currently pointing at?" The answer is almost always: use them together (if compatible) or skip one. That's the universal pattern for LCS, Edit Distance, Interleaving, and Distinct Subsequences.

Why each variable changes

CASE: text1[i] == text2[j] (Match)
Action: Take this character as part of the LCS.
Immediate reward: +1. LCS length grows by 1.
State changes:
i → i+1: text1[i] consumed. It matched. Move past it.
j → j+1: text2[j] consumed. Same character, same match. Move past it.
Call: 1 + lcs(i+1, j+1)
Why both advance? A match consumes one character from each string. Advancing only one would leave the matched character available for a double-count.
CASE: text1[i] != text2[j] (No Match)

Skip one character. Try both options, keep the better result.

Skip text1[i]
Reward: +0. Skipping adds nothing.
State changes: i → i+1 (skipped). j stays (still needs a match).
Call: lcs(i+1, j)
Skip text2[j]
Reward: +0. Skipping adds nothing.
State changes: i stays (still needs a match). j → j+1 (skipped).
Call: lcs(i, j+1)
Decision: max(skip_first, skip_second). We want the longest, so take the better skip.

Step 2: Choices → Recursion

The code writes itself from the choices

def lcs_length(text1, text2, i, j):
    if i == len(text1) or j == len(text2):
        return 0

    if text1[i] == text2[j]:
        return 1 + lcs_length(text1, text2, i + 1, j + 1)

    skip_first = lcs_length(text1, text2, i + 1, j)
    skip_second = lcs_length(text1, text2, i, j + 1)
    return max(skip_first, skip_second)

def lcs_length(text1, text2, i, j, cache):
    if i == len(text1) or j == len(text2):
        return 0
    if (i, j) in cache:
        return cache[(i, j)]

    if text1[i] == text2[j]:
        result = 1 + lcs_length(text1, text2, i + 1, j + 1, cache)
    else:
        skip_first = lcs_length(text1, text2, i + 1, j, cache)
        skip_second = lcs_length(text1, text2, i, j + 1, cache)
        result = max(skip_first, skip_second)

    cache[(i, j)] = result
    return result

What does each cell mean?

The rules at each cell

MATCH

Diagonal + 1. Both chars consumed.
NO MATCH

The Tabulation Code

Row by row, left to right

def lcs_length(text1, text2):
    rows = len(text1)
    cols = len(text2)
    table = [[0] * (cols + 1) for _ in range(rows + 1)]

    for i in range(1, rows + 1):
        for j in range(1, cols + 1):
            if text1[i - 1] == text2[j - 1]:
                table[i][j] = table[i - 1][j - 1] + 1
            else:
                table[i][j] = max(table[i - 1][j], table[i][j - 1])

    return table[rows][cols]

1 Unique Paths

▶
LEETCODE #62
A robot starts at the top-left of an m x n grid. It can only move down or right. Count the number of unique paths to the bottom-right corner.
Example:
m = 3, n = 3 (a 3x3 grid)

start→→ ↓↓ →→end


One path: right, right, down, down. Another: down, right, down, right.
Answer: 6 unique paths total.
m = 2, n = 2 → 2 — Right then down, or down then right. Simplest case.
m = 1, n = 5 → 1 — Single row. Only one path: all right.
THE KEY IDEA
No match/no-match here. Every cell gets its value from exactly two neighbors: the cell above and the cell to the left. table[r][c] = table[r-1][c] + table[r][c-1]. First row and first column are all 1's (only one way to get there).

Why each variable changes

Move DOWN
Action: Robot moves one cell down.
Immediate reward: +0. Moving doesn't add paths, it's one step toward the destination.
State changes:
r → r+1: Moved down one row.
c stays the same: Didn't move horizontally.
Call: count_paths(r+1, c)
Why doesn't c change? Moving down is purely vertical. The column position is unchanged.
Move RIGHT
Action: Robot moves one cell right.
Immediate reward: +0. Just another step toward the destination.
State changes:
r stays the same: Didn't move vertically.
c → c+1: Moved right one column.
Call: count_paths(r, c+1)
Why doesn't r change? Moving right is purely horizontal. The row position is unchanged.
Final decision: result = down + right. We count all paths, so we add the counts from both directions.

Recursion

def count_paths(rows, cols, r, c, cache):
    if r == rows - 1 and c == cols - 1:
        return 1
    if r >= rows or c >= cols:
        return 0
    if (r, c) in cache:
        return cache[(r, c)]

    go_down = count_paths(rows, cols, r + 1, c, cache)
    go_right = count_paths(rows, cols, r, c + 1, cache)
    cache[(r, c)] = go_down + go_right
    return cache[(r, c)]

Tabulation

def count_paths(rows, cols):
    table = [[1] * cols for _ in range(rows)]

    for r in range(1, rows):
        for c in range(1, cols):
            table[r][c] = table[r - 1][c] + table[r][c - 1]

    return table[rows - 1][cols - 1]
Simplest 2D table: no conditions, just add up + left. First row and first column all 1's (one straight-line path). Pascal's triangle rotated.

2 Edit Distance

▶
LEETCODE #72
Given two words, find the minimum number of operations (insert, delete, replace) to transform word1 into word2.
Example:
word1 = "horse", word2 = "ros"

replace h with r → "rorse"
delete r → "rorse" → "rose"
delete e → "rose" → "ros"

Answer: 3 operations (one replace, two deletes).
word1 = "abc", word2 = "abc" → 0 — Same string. No edits needed.
word1 = "intention", word2 = "execution" → 5 — 3 replaces, 1 delete, 1 insert.

What do I need to know?

THE STATE
min_edits(i, j) = minimum operations to transform word1[i:] into word2[j:].

i = how far we've processed in word1. Characters word1[0..i-1] are already handled.
j = how far we've processed in word2. Characters word2[0..j-1] are already produced.

The choices at state (i, j)

We're looking at word1[i] and word2[j]. Either they match or they don't.

CASE: word1[i] == word2[j] (Match)
Action: Characters already match. No operation needed. Move past both.
Immediate cost: +0. A match is free because the character is already correct.
State changes:
i → i+1: We consumed word1[i]. It matched, so it's handled.
j → j+1: We produced word2[j]. The match covers it.
Remaining subproblem: Transform word1[i+1:] into word2[j+1:].
Call: min_edits(i+1, j+1)
Why not (i+1, j) or (i, j+1)? Both characters are dealt with. Advancing only one would leave a character unmatched that we already know matches.
CASE: word1[i] != word2[j] (No Match)

Three operations. Each has cost 1. Each changes the state differently.

Operation 1: REPLACE word1[i] with word2[j]
Action: Overwrite word1[i] so it becomes word2[j].
Immediate cost: +1. One replace operation used.
State changes:
i → i+1: word1[i] is now correct (we replaced it). Move past it.
j → j+1: word2[j] is now produced (by the replacement). Move past it.
Remaining subproblem: Transform word1[i+1:] into word2[j+1:].
Call: 1 + min_edits(i+1, j+1)
Why both advance? Replace handles both positions at once: it consumes word1[i] and produces word2[j] in a single operation.
Operation 2: DELETE word1[i]
Action: Remove word1[i] from word1. It doesn't correspond to anything in word2.
Immediate cost: +1. One delete operation used.
State changes:
i → i+1: word1[i] is deleted, so we move past it.
j stays the same: We haven't produced any character of word2 yet. word2[j] still needs to be handled.
Remaining subproblem: Transform word1[i+1:] into word2[j:]. (Same j, word2 hasn't progressed.)
Call: 1 + min_edits(i+1, j)
Why doesn't j change? Deleting from word1 doesn't produce anything in word2. The target character word2[j] is still waiting.
Operation 3: INSERT word2[j] before word1[i]
Action: Insert the character word2[j] into word1 at position i. This produces the needed character.
Immediate cost: +1. One insert operation used.
State changes:
i stays the same: We didn't consume any character from word1. word1[i] is still there, waiting to be dealt with.
j → j+1: We produced word2[j] (by inserting it). Move past it.
Remaining subproblem: Transform word1[i:] into word2[j+1:]. (Same i, word1 hasn't progressed.)
Call: 1 + min_edits(i, j+1)
Why doesn't i change? Inserting adds a new character. It doesn't consume word1[i]. That character still needs to be matched, replaced, or deleted later.
Final decision: result = min(replace, delete, insert). We want the cheapest path.

Base cases (derived from the state)

i == len(word1)
Situation: We've consumed all of word1, but word2[j:] still has characters left.
Only option: Insert every remaining character of word2.
Cost: len(word2) - j (one insert per remaining character).
This is NOT 0 like LCS. There's still work to do.
j == len(word2)
Situation: We've produced all of word2, but word1[i:] still has characters left.
Only option: Delete every remaining character of word1.
Cost: len(word1) - i (one delete per remaining character).
Extra word1 characters are baggage. They must go.

Recursion (with memoization)

def min_edits(word1, word2, i, j, cache):
    if i == len(word1):
        return len(word2) - j
    if j == len(word2):
        return len(word1) - i
    if (i, j) in cache:
        return cache[(i, j)]

    if word1[i] == word2[j]:
        result = min_edits(word1, word2, i + 1, j + 1, cache)
    else:
        replace = 1 + min_edits(word1, word2, i + 1, j + 1, cache)
        delete = 1 + min_edits(word1, word2, i + 1, j, cache)
        insert = 1 + min_edits(word1, word2, i, j + 1, cache)
        result = min(replace, delete, insert)

    cache[(i, j)] = result
    return result

TABLE MAPPING
Row i = how much of word1 we've processed (0 to len(word1)).
Col j = how much of word2 we've produced (0 to len(word2)).
table[i][j] = min operations to transform word1[i:] into word2[j:].

Edges: table[i][0] = i (delete all remaining word1). table[0][j] = j (insert all remaining word2).

def min_edits(word1, word2):
    rows = len(word1)
    cols = len(word2)
    table = [[0] * (cols + 1) for _ in range(rows + 1)]

    for i in range(rows + 1):
        table[i][0] = i
    for j in range(cols + 1):
        table[0][j] = j

    for i in range(1, rows + 1):
        for j in range(1, cols + 1):
            if word1[i - 1] == word2[j - 1]:
                table[i][j] = table[i - 1][j - 1]
            else:
                table[i][j] = 1 + min(
                    table[i - 1][j - 1],
                    table[i - 1][j],
                    table[i][j - 1]
                )

    return table[rows][cols]

LCS vs Edit Distance: same grid, different goal

LCS (parent)
Match: diagonal + 1 (count it!)
No match: max(up, left)
Goal: maximize matches
Base case: 0 (nothing to match)
2 choices on mismatch
Edit Distance
Match: diagonal + 0 (free!)
No match: 1 + min(diag, up, left)
Goal: minimize operations
Base case: remaining length
3 choices on mismatch
Why the directions map to operations:
Diagonal (i+1, j+1) = replace. Both pointers advance because replace handles both positions.
Up (i+1, j) = delete. Only i advances because we removed from word1, word2 hasn't progressed.
Left (i, j+1) = insert. Only j advances because we added to word2's production, word1 hasn't been consumed.

3 Interleaving String

▶
LEETCODE #97
Given strings s1, s2, and s3, check if s3 can be formed by interleaving s1 and s2 while keeping their character order.
Example:
s1 = "aab", s2 = "axy", s3 = "aaxaby"

Interleave: aaxaby (s1 chars, s2 chars)
Both strings keep their original order. Answer: True.

s1 = "ab", s2 = "cd", s3 = "acdb" → True (acdb)
s1 = "ab", s2 = "cd", s3 = "abdc" → True (abdc)
Not allowed: rearranging characters within s1 or s2. Only the interleaving order changes.

Why not just greedy?

If only one string matches the next character in s3, you pick it. But when both s1[i] and s2[j] match, picking the wrong one leads to a dead end. You need to try both paths.

THE KEY IDEA
table[i][j] = True if s3[:i+j] can be formed from s1[:i] and s2[:j]. At each cell, the next character in s3 is s3[i+j-1]. It came from either s1 (above) or s2 (left).

Why each variable changes

State: can_interleave(i, j). We need to produce s3[i+j] next. It must come from either s1[i] or s2[j].

Take from s1 (when s1[i] == s3[i+j])
Action: Use s1[i] to produce s3[i+j].
State changes:
i → i+1: s1[i] consumed. It produced the next character of s3.
j stays the same: s2[j] not used. Still available.
Call: can_interleave(i+1, j)
Why doesn't j change? We took from s1, not s2. s2[j] is still the next available character from s2.
Take from s2 (when s2[j] == s3[i+j])
Action: Use s2[j] to produce s3[i+j].
State changes:
i stays the same: s1[i] not used. Still available.
j → j+1: s2[j] consumed. It produced the next character of s3.
Call: can_interleave(i, j+1)
Why doesn't i change? We took from s2, not s1. s1[i] is still available.
Decision: If either path returns True, the interleaving works. OR logic, not max/min.

Recursion

def can_interleave(s1, s2, s3, i, j, cache):
    if i + j == len(s3):
        return i == len(s1) and j == len(s2)
    if (i, j) in cache:
        return cache[(i, j)]

    result = False
    if i < len(s1) and s1[i] == s3[i + j]:
        result = can_interleave(s1, s2, s3, i + 1, j, cache)
    if not result and j < len(s2) and s2[j] == s3[i + j]:
        result = can_interleave(s1, s2, s3, i, j + 1, cache)

    cache[(i, j)] = result
    return result

Tabulation

def can_interleave(s1, s2, s3):
    if len(s1) + len(s2) != len(s3):
        return False

    rows = len(s1)
    cols = len(s2)
    table = [[False] * (cols + 1) for _ in range(rows + 1)]
    table[0][0] = True

    for j in range(1, cols + 1):
        table[0][j] = table[0][j - 1] and s2[j - 1] == s3[j - 1]

    for i in range(1, rows + 1):
        table[i][0] = table[i - 1][0] and s1[i - 1] == s3[i - 1]

    for i in range(1, rows + 1):
        for j in range(1, cols + 1):
            from_s1 = table[i - 1][j] and s1[i - 1] == s3[i + j - 1]
            from_s2 = table[i][j - 1] and s2[j - 1] == s3[i + j - 1]
            table[i][j] = from_s1 or from_s2

    return table[rows][cols]
The twist: no "match" in the LCS sense. Instead, check if the next char in s3 came from s1 (look up) or s2 (look left). Boolean cells instead of counts.

4 Distinct Subsequences

▶
LEETCODE #115
Given strings s and t, count how many distinct subsequences of s equal t.
Example:
s = "rabbbit", t = "rabbit"

s has three b's. To spell "rabbit" you need two b's. Which two do you pick?
Way 1: rab1b2it
Way 2: rab1_b3it
Way 3: ra_b2b3it

Answer: 3 distinct subsequences.
You're not rearranging anything. You're choosing which characters in s to "use" to form t, keeping the order.
s = "babgbag", t = "bag" → 5 — 3 b's, 2 a's, 2 g's. Five ways to spell "bag".
s = "aabb", t = "ab" → 4 — 2 a's × 2 b's = 4 ways to pick one of each.
CLASSIFICATION
What does it compute? Count the number of ways to form one string from another by choosing characters.
Why not greedy? Greedy picks the first matching character. But we need ALL ways, not just one. Skipping a match now might lead to more total subsequences through later duplicates.
Which family? 2D table (two strings, one grid). Same grid as LCS, but counting paths instead of maximizing length.
RECURSIVE QUESTION
"In how many ways can I form t[j:] using characters from s[i:]?"

Plain English first: I'm looking at position i in s and position j in t. How many different ways can I pick characters from s (starting at i) that spell out the rest of t (starting at j)?

When must I stop?

Before thinking about choices, ask: "When is the answer obvious without any recursion?"

j == len(t): all of t is matched
Situation: I've matched every character of t. Nothing left to spell.
Why stop? The target string is fully formed. No more work to do.
Return: 1. This IS one valid subsequence. I found a complete way.
NOT 0. Reaching the end means success, so count it as one way.
i == len(s): ran out of s characters
Situation: I've exhausted s, but t[j:] still has unmatched characters.
Why stop? No more characters in s to pick from. Can't finish spelling t.
Return: 0. No way to complete the match.
Order matters: check j == len(t) FIRST. If both exhausted, the answer is 1 (success), not 0.
CHOICES (DISCOVERED, NOT LISTED)
Situation: I'm at s[i] and I need to match t[j] next.
The natural first question: Does s[i] match t[j]?

If they match: I have a real choice. I can USE s[i] to cover t[j], or I can SKIP it (maybe a later copy of this character leads to more subsequences). Both are valid, so I count both and add.
If they don't match: s[i] can't help with t[j]. Only option is to skip it.

Why is "use + skip" the key insight? In LCS, a match is always taken (no reason to skip a free match when maximizing). Here I'm COUNTING all ways. Even when characters match, skipping can lead to different valid subsequences through later duplicates. Both paths contribute to the total count.

Why can't I skip t[j]? t is the target. Every character of t must be matched. Skipping a character of t would change what I'm trying to spell. I can only skip characters of s (choosing which copies to use).

Why each variable changes

CASE: s[i] == t[j] (Match)

Two options. Characters match, but I can USE this match or SKIP it. Count both paths (add them).

Option 1: USE s[i] to match t[j]
Action: Use s[i] to match t[j]. Both characters consumed.
State changes:
i → i+1: s[i] consumed (used for the match). Move past it.
j → j+1: t[j] matched. Move to the next target character.
Call: count_subsequences(i+1, j+1)
Why both advance? Using s[i] to match t[j] consumes one character from each string. Both positions are handled.
Option 2: SKIP s[i] (even though it matches)
Action: Skip s[i]. Maybe a later copy of this character leads to more subsequences.
State changes:
i → i+1: s[i] skipped. Move past it.
j stays the same: t[j] not matched yet. Still needs to be covered by a later character.
Call: count_subsequences(i+1, j)
Why doesn't j change? I chose not to use this match. t[j] still needs to be matched by a later s character.
Decision: result = use + skip. Counting all distinct subsequences, so ADD both paths.
CASE: s[i] != t[j] (No Match)
Action: s[i] can't match t[j]. Only option: skip it.
State changes:
i → i+1: s[i] skipped (useless for current target).
j stays the same: t[j] still waiting to be matched.
Call: count_subsequences(i+1, j)

Watch it play out

Trace s="rabbbit", t="rabbit", starting at i=0, j=0:

i=0, j=0: s[0]='r' == t[0]='r'. Match! Use it (i=1, j=1) + skip it (i=1, j=0). Follow the "use" path:
i=1, j=1: s[1]='a' == t[1]='a'. Match! Use it. Now i=2, j=2.
i=2, j=2: s[2]='b' == t[2]='b'. Match! Here's where it branches:
USE b1: count_subsequences(3, 3) (used first b)
SKIP b1: count_subsequences(3, 2) (save for later b's)
The branching at b's is exactly why there are 3 ways. Three b's, need two, and C(3,2) = 3.

Recursion

def count_subsequences(s, t, i, j, cache):
    if j == len(t):
        return 1
    if i == len(s):
        return 0
    if (i, j) in cache:
        return cache[(i, j)]

    skip_char = count_subsequences(s, t, i + 1, j, cache)
    if s[i] == t[j]:
        use_char = count_subsequences(s, t, i + 1, j + 1, cache)
        result = use_char + skip_char
    else:
        result = skip_char

    cache[(i, j)] = result
    return result

Tabulation

TABLE MAPPING
Row i = how much of s we've considered (0 to len(s)).
Col j = how much of t we need to match (0 to len(t)).
table[i][j] = number of ways to form t[:j] from s[:i].

Base cases in the table:
table[i][0] = 1 for all i: empty t can always be formed (one way: pick nothing).
table[0][j] = 0 for j > 0: empty s can't form any non-empty t. 
def count_subsequences(s, t):
    rows = len(s)
    cols = len(t)
    table = [[0] * (cols + 1) for _ in range(rows + 1)]

    for i in range(rows + 1):
        table[i][0] = 1

    for i in range(1, rows + 1):
        for j in range(1, cols + 1):
            table[i][j] = table[i - 1][j]
            if s[i - 1] == t[j - 1]:
                table[i][j] += table[i - 1][j - 1]

    return table[rows][cols]

LCS vs Distinct Subsequences: same grid, different operation

LCS (parent)
Match: take it (diagonal + 1)
No match: max(skip from s, skip from t)
Goal: maximize match length
Two-sided skipping
Distinct Subsequences
Match: use + skip (diagonal + up)
No match: skip only (up)
Goal: count all paths
One-sided skipping (only from s)
Why one-sided skipping? In LCS, both strings are equal partners, so you can skip from either. In Distinct Subsequences, t is the target. You never skip characters of t (that would change what you're trying to spell). You only skip characters of s (choosing which copies to use).
Familiar pattern: this is knapsack's "grab + skip" on strings. Match = use (diagonal) + skip (up). No match = skip (up only). Count, not max. The difference from LCS: match uses ADD (count both paths), not "take the match and move on."
